### 표 C — 질문 종류별 비교

## 2. 1차 검색 비교군을 늘리는 축

| 축 | 비교군 | 해석·통제 |
|---|---|---|
| 검색 채널 | dense-only / BM25-only / hybrid | 동일 필터와 최종 후보40. dense·BM25 각각이 회복하는 정답과 교집합/합집합 기록 |
| 결합 | RRF 가중치0.5/1/2, RRF 상수 변화; 이후 필요시 정규화 점수 결합 | 테스트 정답을 보고 최적 가중치를 고르지 않고 개발 구간에서 선택 |
| 질의 출처 | 현재 사실 질의 / 원질문 / 사실 질의+원질문 | 같은 계획의 범위·역할은 유지. 질의 수 증가에 따른 시간도 기록 |
| 복합 사실 | 유도·유지를 묶은 질의 / 사실별로 분리한 질의 | 후보 예산을 같게 맞춰 분리 효과와 단순 후보 증가 효과 구분 |
| 식별자 | 현재 / 원질문의 시험번호·Part·표번호를 추가 BM25 질의로 사용 | 질문에 실제 등장한 식별자만 사용. 문항별 정답 규칙 금지 |
| BM25 텍스트 | 본문 / 본문+절 경로·캡션 / 공통어 제거 on/off | 임베딩 입력은 그대로 유지하여 lexical 필드 효과만 비교 |
| 문서 역할 | role boost on/off, correspondence 기본 포함/계획 선택시 포함 | 같은 범위 안 경쟁과 풀 회수 모두 기록. 범위를 넓히는 것을 자동 개선으로 보지 않음 |
| 통계표 보정 | on/off | 요청 통계량·시험 조건을 유지. 일반 텍스트 질문에서 회귀도 확인 |
| 후보 예산 | 채널별 검색 깊이20/40/80과 최종 풀20/40/60을 별도로 조절 | 채널 검색 깊이와 리랭커 입력 풀 크기를 구분. 같은 품질 예산 비교와 품질-시간 곡선을 각각 제시 |

전 조합의 Cartesian product는 만들지 않는다. 현재 구성에서 한 요소씩 바꾸는 비교 → 효과 있는 요소의 조합 → 같은 2차에서 확인하는 순서가 원인을 설명하기 쉽다. 임베딩 모델 변경은 별도 실험으로 분리한다.

질문 확장도 두 가지를 구분한다.

- **의미를 유지한 표현 변경:** 같은 답을 기대한다. 동의어, 어순, 한국어/영어, 약어/풀네임. 변형들은 같은 원질문 family로 묶어 집계한다.
- **한 조건만 바꾼 최소쌍:** 정답이 달라져야 한다. 시험번호/Part, 적응증, IV/SC, 최초/보충 허가, 산술/기하평균, PFS/바이알. 조건을 바꿨는데 같은 근거를 고집하는지 검사한다.

대상 명시 QA / 대상 생략 QA / UI에서 문서 고정 QA도 구별한다. 일부 실험에서는 사람 확인 범위를 고정해 검색 알고리즘만 검사하고, 별도 반복계획 실험에서는 실제 범위 해석까지 평가한다. 사람 확인 범위의 결과는 진단용 통제이며 실제 자동 서비스 성능과 별도다.

## 3. nDCG·MRR 진단

### 3.1 기존 결과에서 실제 순위를 다시 집계

[원결과](../../data/runs/retrieval_gold_2026-10-16/model40_bge.json)의 weak 제외235묶음을 그대로 사용했다. 아래는 새 실행이 아닌 저장 rank의 집계다. [집계 JSON](RANK_DIAGNOSTICS_2026-10-19.json).

| 정답 묶음의 최선 순위 | 리랭커 없음 | 현재 방식 fquery_unit+RRF |
|---|---:|---:|
| 1위 | 84 | 115 |
| 2~3위 | 48 | 53 |
| 4~8위 | 36 | 30 |
| 9~40위 | 43 | 13 |
| 후보 풀 없음 | 24 | 24 |

현재 방식은198/235묶음을8위 안에서 찾지만1위는115/235(48.9%)다. 24묶음(10.2%)은 리랭커에 입력되지 않고13묶음(5.5%)은 입력됐어도8위 밖이다. 나머지83묶음은8위 안에 있어도1위보다 순위 점수가 낮다. 따라서 Recall@8=.843과 MRR=.617은 모순이 아니다.

기존 정의의 nDCG는8위 안198묶음의 평균 할인점수 약.794와 전체 회수율.843을 곱하면 약.669가 된다. 기존 MRR는 풀 회수율211/235와 회수된 묶음의 평균 역순위 약.687을 곱하면 약.617이다. 1/MRR를 평균 정답 순위로 읽으면 안 된다.

| 집단 | Recall@8 | 기존 nDCG@8 | 기존 MRR | 풀 상한 |
|---|---:|---:|---:|---:|
| fact_gold | .928 | .762 | .710 | .971 |
| QA_candidates | .750 | .539 | .474 | .750 |
| e2e29 | .825 | .660 | .611 | .905 |

QA는 풀 안의 정답을 모두8위 안으로 올려도 recall이.750이다. 이 집단의 추가 회수 개선에는1차 후보 검색·질의·범위의 검사가 필요하다. 저하 원인을 모두 리랭커 탓으로 돌릴 수 없다. 그 외 알려진 실패에는 여러 사실의 질의 합쳐쓰기, 조건/식별자 누락, 동일 그룹에서 사실 간 순위 경쟁, 짧은 날짜·수치 근거가 밀리는 현상이 있다. 각 원인의 기여량은 앞의 통제 비교로 확인해야 한다.

### 3.2 현재 지표는 표준 정의와 차이가 있음

[채점 코드](../../eval/retrieval_gold.py)의 `ndcg`는 각 사실의 최선 순위에 할인점수를 주고 사실 수로 나눈다. 모든 사실이1위인 경우를 만점으로 놓는다. 서로 다른 사실이 서로 다른 청크에 있고 같은 그룹 목록을 공유하면 전부1위가 될 수 없다.

예를 들어 정답2개가1·2위에 완벽하게 배치돼도 현재 값은 `(1 + 1/log2(3))/2 = .815`다. 표준 nDCG는 그 relevance 목록의 실제 이상적 DCG로 나누므로 해당 이상적 배치에서1이다. 표준 정의는 [scikit-learn 공식 문서](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.ndcg_score.html)를 참고한다.

현재 MRR도 질문별 첫 정답의 역순위가 아니라 정답 사실마다 최선 순위를 구해 평균한다. 위 두 사실의 현재 값은 `(1+1/2)/2=.75`지만 질문의 첫 정답 기준 RR는1이다. 질문별 첫 relevant 결과를 사용하는 정의는 [Microsoft 공식 설명](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/rag/rag-information-retrieval)을 따른다.

권장 보고 방식:

1. 현재 수치는 '사실별 할인 순위 평균', '사실별 역순위 평균'이라는 설명을 붙여 역사 비교를 유지한다.
2. 검색 그룹별 relevance 목록으로 표준 nDCG@8·MRR@8을 추가한다. 관련성 라벨은 예를 들어 충분한 직접 근거2 / 일부 관련 맥락1 / 무관·다른 시험0으로 사전 정의한다. 같은 근거의 중복 청크가 여러 보상을 받지 않도록 평가 단위를 정한다.
3. 여러 사실을 다 찾아야 하는 업무에는 사실 recall·모든 필수 사실 충족률을 함께 둔다. 첫 정답 하나를 찾는 표준 MRR만 높이는 것으로 전체 요구 충족을 설명하지 않는다.
4. 페이지 hit와 실제 셀/문장 hit를 따로 보고한다. 현재 페이지 판정은 오히려 성공을 넓게 인정하는 면도 있어 지표 정의만 바꾸면 실제 품질 문제가 해결된다고 결론 내릴 수 없다.

## 4. 전처리 비교는 무엇을 입증하는가

**현재 프로젝트에서 H 구성을 선정하는 근거는 성립한다.** 같은 입력·공통 평가에서 실제 선택 출력이 개선됐고, G′/H는 같은 새 기본 추출과 독립 검출을 공유하며 각 VLM 분기는 새로 실행했다. 고정 셀79→88, 기존 성공 셀 손실0은 H 보완 묶음의 효과를 뒷받침한다. 근거: [최종 선정 보고서](../preprocessing/FINAL_PREPROCESSING_DECISION_2026-10-14.md), [동결 정책](../../pipelines/pipeline_h/vendor/compare_study_standalone/output/abp654_design_20261014_v2/policy.json).

다음 주장은 추가 통제가 필요하다.

|---|---|---|
