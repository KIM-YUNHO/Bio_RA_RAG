### 4.3 지표의 정확한 의미

- **R@k:** 각 정답 묶음의 `(문서 ID, PDF 쪽)` 중 하나가 검색 그룹들의 상위 k 안에 있으면 성공. 여러 그룹 중 최선 순위를 사용해 235묶음에서 평균한다.
- **풀 상한:** 후보 풀 안에 정답 페이지가 존재하는 비율. 풀 밖 근거는 리랭커만으로 회복할 수 없다.
- **nDCG@k:** 묶음별 최선 순위에 `1/log2(rank+1)`을 주고 k 밖은 0, 모든 묶음이 1위인 경우를 이상값으로 삼는다. 일반적인 단일 순위 목록의 graded-relevance nDCG와 동일하게 취급하지 않는다.
- **MRR:** 묶음별 최선 순위 역수의 평균. 풀 밖은 0이며 @8로 자른 MRR가 아니다.
- **flip:** 같은 문항에 대해 새로 만든 4계획 사이에서 발견/실패가 바뀌는 정답 묶음 비율.
- **안정성 최저:** 문항별 4계획 최저 recall을 구한 뒤 정답 묶음 수로 가중 평균한다. 전체셋의 한 번의 최악 실행 점수는 아니다.

같은 페이지의 다른 청크를 찾아도 hit가 될 수 있다. 따라서 이 지표는 필요한 셀·조건·문장이 입력에 들어왔는지, precision, 최종 답변 충족률을 직접 평가하지 않는다. 근거: [검색 채점 코드](../../eval/retrieval_gold.py), [안정성 채점 코드](../../eval/plan_stability.py).

| P2 | fquery_unit에서 풀20/40/60·k8/12 | 위 동결 계획·동일 질의. GPU·캐시 조건 고정 | 현 질의의 품질/지연 절충. 기존 ask 기반 풀 선택 보완 | 약1~2시간 |
| P2 | H 기본 추출 대 최종 선택 | ABP654 외4제품, 기관·scan/native·표유형 층화18~24쪽 | 15쪽 개발 표본 밖의 회고 품질 검사 | 약3~4시간 |

최소 당일 산출물은 P0 두 개와 P1 중 하나로 잡는 것을 권한다. H 비교는 이미 처리한 문서의 회고 표본감사이므로 독립 신규 문서 일반화로 부르지 않는다. 모델 출력을 보기 전에 정답·판정 기준을 확정하고, 출력 검토 중 수정하면 해당 자료를 개발셋으로 전환한다.

### 8.3 비교를 엄밀하게 만드는 공통 조건

1. 릴리스·청크 해시, 코드/프롬프트·프로파일·모델 식별, UI 범위·계획·후보 풀을 저장한다. 리랭커 효과를 볼 때는 계획·풀을 동일하게 하고, 계획기 효과는 별도 반복한다.
2. 기존 개발셋, 질문 조건을 고친 버전, 새 사람 작성 문항을 각각 보고한다. 보호 해제9문서를 독립 문서셋으로 돌리지 않는다. 실제 미노출 문서 평가는 노출 기록과 별도 승인된 주석 자료가 필요하다.
3. 1차는 dense-only / BM25-only / 현재 hybrid를 같은 필터·후보 예산에서 비교한다. 역할 가산·correspondence·통계표 모듈은 한 번에 하나씩만 바꾼다. 2차는 같은 풀의 없음 / ask / fquery + RRF로 비교한다.
4. R@40·R@8·순위 지표 외에 **정답 문장/셀과 조건의 입력 포함률**, 잘못된 시험·기관 회수, 원문 부재 처리, 기존 성공의 손실도 센다. H는 셀 문자뿐 아니라 군·값·단위·각주 관계와 후보 오채택/미채택을 센다. gate 감사는 층별 분자/분모·오채택 사례를 우선 보고한다. 층화 표본의 단순 채택 precision을 전체 모집단의 추정치로 쓰지 않으며, 전체 추정이 필요하면 층별 모집단 비율로 가중한다.
5. 검색 차이는 질문별 짝 비교로 계산한다. 같은 질문의 여러 정답 묶음·4계획을 독립 표본으로 늘려 세지 않는다. 질문 단위 bootstrap 차이 구간과 개선/악화 문항 수를 함께 남긴다. H 비교는 문서 또는 문서 family 단위로 짝 비교·재표집하며, 같은 문서의 셀을 독립 표본으로 세지 않는다. 문항·문서가 적으면 유의성 확정보다 사례와 구간을 보고한다.
6. 지연은 cold 시작·warm 1차·2차·패킹·전체 응답을 나누고 캐시 상태·GPU 동시 작업·그룹/사실 수를 기록한다. 소표본은 중앙값·최대/개별값을, 충분한 반복이 있으면 p95를 보고한다. 배치1/2/4 속도는 동일 crop20~40개로 순서를 바꿔3회씩 측정하고 출력·gate 일치도 확인한다.
7. 마지막으로 검색 이득이 있었던 조건부·복합 질문의 최종 답변을 제한 재평가한다. 검색 recall 상승만으로 서비스 채택을 결정하지 않는다.
