# 전처리 파이프라인 확정과 임베딩 완료

2026-10-10 KST. 사용자 지정 1차 목표의 실행 기록이다. 전처리는 원본 등록부터 임베딩·색인 검증까지다. 시각별 중단 계획을 적용하지 않고 원칙에 따라 실행한 뒤 실패를 점검한다.

범위는 EMA/FDA/HC 5상품의 승인 92문서다. 기존 보류 9문서는 제외한다. 원본·이전 추출·릴리스는 보존하며 새 실행은 별도 출력으로 만든다. 기본 검색 선택 정책은 전처리 대상이나 임베딩 대상에서 문서를 제외하는 기준으로 사용하지 않는다.

## 실행 파이프라인

1. 원본/렌더/문서 버전/처리 범위를 확인한다.
2. 신뢰할 수 있는 native 표현을 재사용하고 일반 영역은 PaddleOCR로 처리한다. 완료한 일반 OCR 996영역은 반복하지 않는다.
3. 원본 격자·문자 좌표·기존 OCR로 표 구조를 복구한다. 캡션·각주·본문은 본체와 분리해 연결한다.
4. 독립적으로 복잡성이 확인된 미해결 영역만 Qwen으로 보완한다. 격자가 확인된 표는 구조를 고정하고 미해결 셀 문자만 읽는다. 자유 구조 생성의 실패를 같은 입력으로 반복하지 않는다.
5. 표·그림·절·시험·출처·좌표·검증 상태를 연결하고 청킹한다. 불확실한 수치를 정상 근거로 승격하지 않는다.
6. 확정된 청크를 임베딩한다. 이전 실제 임베딩 입력/모델/설정이 같으면 검증해 재사용하고 변경 입력만 계산한다.
7. 92문서 버전/청크/벡터/출처 명세, 누락·중복·입력 잘림·보류 누출을 검사한다.
8. 처리 완료와 품질 보류를 구분한 최종 명세를 남긴다. 이후 실패 유형별로 트러블슈팅하고 RAG 평가를 진행한다.

## 시작 상태

이전 릴리스 `corpus_update_2026-10-09_updated_v1`은 92문서·10,048청크와 임베딩이 생성돼 있다. 일반 OCR 996영역, 모델 없는 표 구조 복구 41개, 복잡 영역 Qwen 39개 처리는 완료했다. 자유 구조 생성 결과의 복잡 표 22개는 채택을 보류했다. 이 22개를 원본 격자 고정·셀 단위 문자 연결 방식으로 처리하는 것이 현재 전처리 보완 대상이다.

시작 시점에는 새 방식의 구현·처리·임베딩은 아직 완료되지 않았다. OpenAI 추가 호출과 서비스 재시작은 이 목표에 포함하지 않는다.

## 이번에 구현한 구조 복원 단계

`preprocess/source_grid.py`는 원본 테두리로 확인한 논리 위치·병합 범위·물리 셀 좌표를 고정한다. 각 셀에 검증된 native 문자 또는 기존 일반 OCR 토큰을 연결하고, 실제 빈 칸·비공개·미판독을 구분한다. 검증 가능한 원문 제목·각주는 격자와 별도로 보존한다. 셀만 채워졌다는 이유로 전체 표를 완료 처리하지 않고, 원본 영역에 속한 미배치 문자와 OCR 토큰도 검사한다.

레이아웃 crop이 외곽선을 잘랐을 때 원본 PDF를 최대 4 pt 여백으로 다시 렌더해 실제 경계를 확인한다. 이 과정은 문자 인식 모델을 호출하지 않는다. 격자나 문자 근거가 부족하면 기존 표현과 보류 상태를 유지한다. 삽화가 들어 있는 셀은 읽을 수 있는 문자 라벨만 보존하고 그림 설명 검토 상태를 남긴다. 연속 표의 관계도 문자 복원만으로 확정하지 않는다.

`preprocess/grid_refinement.py`는 완료된 추출 번들을 검증하고 별도 스냅샷에 적용한다. 일반 OCR 영역 처리에서도 구조 복원을 먼저 시도한다. 새 결과를 불러올 때 `hybrid_validate.py`가 원본 테두리·셀 문자·좌표·OCR·표현을 재계산해 확인한다. 이전 Qwen 후보는 이력으로 보존한다.

`preprocess/queue_finalize.py`는 구조가 미확정인 기존 모델 대기 작업까지 같은 기준으로 확인한다. 문자·구조가 복원되면 채택하고, 복잡성의 독립적인 양성 근거가 없으면 모델 대기열에서 빼 검토 상태로 저장한다. 실제 병합 격자의 미판독 셀이 남으면 완료 처리를 거부한다. 검토 판정도 원본 격자·OCR 상태·이전 분기를 묶어 재검증한다. 검증된 원본 해시가 같은 페이지의 native packet은 작업 내에서 재사용해 동일한 글꼴·표 검사를 반복하지 않는다.

재사용 명령은 다음과 같다. 상품·기관·페이지별 분기가 없으며 승인 범위는 호출 측 명세에서 제한한다.

```powershell
.\.venv\Scripts\python.exe -m preprocess source-grid --run <완료된 추출 번들> --out <새 출력 경로>
.\.venv\Scripts\python.exe -m preprocess.queue_finalize --run <완료된 추출 번들> --out <별도 최종 판정 경로>
.\.venv\Scripts\python.exe -m preprocess chunk --run <새 출력 경로> --out <새 청크 경로>
.\.venv\Scripts\python.exe rag/embed_index.py --rag-dir <새 청크 경로> --model bge-m3 --local-only
```

청킹은 원문 범위 재구성과 토큰 예산을 확인하고 제목·각주 연결을 유지한다. 병합 셀/행을 자를 위험이 있는 큰 표는 명시적으로 보류한다. 이런 보류를 완료한 청크로 바꾸기 위해 내용이나 헤더 역할을 추측하지 않는다.

## 최종 실행과 완료 판정

초기 구조/청크 준비는 `tmp/complete_preprocessing_corpus.py`, 남은 작업 판정과 최종 임베딩은 `tmp/finalize_preprocessing_corpus.py`로 기록한다. 92개 승인 문서의 페이지와 청크를 확인하고, 변경된 추출만 다시 청킹한다. 최종 전체 청크는 로컬 BGE-M3로 한 번 임베딩하며 실제 로드한 모델 텐서·토크나이저·풀링 설정의 지문을 저장한다. 이전 벡터는 새 모델 지문이 없으므로 이번 릴리스에 혼합하지 않는다.
