# 원본 형식·내용 커버리지를 기준으로 하는 일반 보완 설계

2026-10-14. 설계 문서이며 아래 전체 경로가 구현·검증됐다는 의미는 아니다.

구현 현황: DOM 입력 분기, DOM 기반 미리보기/출처, 좌표 복구·경고 분리, 원문 text-node 커버리지 및 청크 처리 내역, 증분 임베딩을 v2에 적용했다. 92문서/11,536벡터 최종 검증과 이전 파일 보호 검사를 통과했다. 표준 패턴 검사18개 통과. 임의의 모든 RA 문서의 의미 정확도 또는 복구 성공을 보장하는 상태는 아니며, 미해결 내용은 검토 근거를 보존해야 한다. 상세 현황은 WORK_LOG.md 및 v2의 FINAL_REPORT.md를 따른다.

## 확인한 원인

- 현재 승인 범위는 PDF82문서, HTML10문서다. HTML도 기존 파생 PDF에 Docling을 적용하는 경로로 처리했다.
- `export.py`는 물리 bbox가 유효하지 않으면 `invalid_source_bbox`를 기록하고 해당 block의 asset 생성을 건너뛴다. 원시 block은 보존됐지만 콘텐츠 위치의 오류가 검색 콘텐츠 제외로 이어졌다.
- HC HTML3문서의 155개 block, PDF16쪽의 17개 문자 block이 이 경로로 제외됐다.
- HC block 중 20자 이상129개 문구가 현재 같은 문서의 chunk.text에서 NFKC/공백 제거/대소문자 통일 후 정확히 확인되지 않았다. 의미 단위 완전 누락 확정과 다르다.
- 최종 기존 source/hash/region 검사는 통과했지만, 원문 콘텐츠의 처리 내역까지 전부 설명하는 검사가 부족했다. 최종 page-status 검사는 좌표 경고와 본문 누락을 모두 실패로 처리했다.

## 입력 형식별 경로

### HTML

원본 DOM에서 제목·절·본문·목록·표·병합 셀·각주·링크·이미지 참조를 직접 읽는다. 파생 PDF는 시각적 검토 보조 자료다. 콘텐츠를 파생 PDF의 bbox 유효성에 종속시키지 않는다.

콘텐츠 위치는 원본 HTML SHA, DOM node path, 원본 문자 start/end, 원문 절 계층으로 관리한다. PDF 페이지와 bbox는 실제 대응이 검증된 경우에만 별도 위치 정보로 기록한다. 없는 PDF 좌표를 임의 생성하지 않는다. 원문 표의 행·열·rowspan/colspan, superscript/subscript를 보존한다. 동일 부모와 자식의 텍스트를 이중 추출하지 않는다. 메뉴·script·style 등 제외는 콘텐츠 유형과 원문 범위를 기록한다.

10개 HTML 전체에 동일 규칙을 적용한다. 이번3문서의 ID·제품·쪽 번호를 분기 조건으로 사용하지 않는다.

### PDF

기존 Heron·PDF 문자층/RapidOCR PP-OCRv6·TableFormer accurate와 선별 PP-DocLayoutV3/PaddleOCR-VL 경로를 유지한다. 물리 좌표 문제를 발견하면 원시 좌표 프레임·회전·cropbox를 확인하고, 독립 PyMuPDF 문자·word bbox에서 같은 문구를 검증해 복구한다. 여러 후보가 있으면 기존 좌표와 문맥을 함께 이용하며 애매한 후보를 임의로 고르지 않는다.

문자층이 손상되거나 정확한 문구/좌표 대응을 확인하지 못하면 원문에서 검증된 layout 영역에 한해 OCR을 재시도한다. 표라면 원시 셀 구조를 보존하고 기존 후보 gate를 적용한다. 복구 실패한 텍스트는 원시 콘텐츠와 위치 실패 이유를 review queue에 남긴다. 좌표 오류를 이유로 내용을 조용히 버리거나 fake bbox로 통과시키지 않는다.

## 콘텐츠·위치·검토 상태 분리

- `content_status`: 원본 DOM/문자층/이미지에서 읽은 내용의 보존·신뢰 상태.
- `locator_status`: 원본 DOM 위치, 검증된 PDF 영역, 대응 미확인 상태.
- `review_reason`: 원시 근거, 보완 방법, 후보 거절, 미해결 내용을 명시.

HTML DOM 원문 위치가 확인되면 PDF 미리보기 좌표가 없어도 검색 콘텐츠를 유지할 수 있다. PDF 본문의 출처 대응이 해결되지 않으면 미해결 내용으로 남긴다. 한 글자라는 이유만으로 경미한 오류로 판단하지 않는다. 단위·지수·부등호·각주·수용체 표기인지 원문 문맥으로 확인한다.

## 새 검증 계약

1. 원본에서 독립 콘텐츠 inventory를 만든다. HTML은 DOM leaf/container 중복을 제거한 원문 블록, PDF는 신뢰 가능한 문자·표·그림 영역과 OCR 필요 영역을 구분한다.
2. 각 원문 단위는 추출·동일 내용 중복 병합·근거 있는 비본문 제외·복구 실패 중 하나의 처리 이력으로 대응돼야 한다.
3. 정상 내용의 한 문구/단위가 사라져도 단순 전체 문자 비율로 덮지 않는다. 수치·단위·연구 ID·절 제목과 표 셀은 별도로 확인한다.
4. 누락 문구 검색은 진단 보조다. 최종 판정은 unit ID·원본 범위·실제 representation 범위 대응으로 수행한다. 의미/추출 정확도를 커버리지 검사와 혼동하지 않는다.
5. 최종 결과에 처리 문서 수, 본문·표·그림·각주 처리 내역, 검색 포함/중복/검토 제외 수, 미해결 목록을 보고한다. 본문 누락과 경미한 위치 경고를 분리한다.

## 기존 메타데이터·청킹·임베딩

문서 ID/version/source SHA, 제품·기관·문서 유형·제목·언어·검색 정책 등 원래 catalog metadata를 유지한다. 절·표/그림·캡션·연구 ID의 구조도 유지한다. 원본 HTML의 DOM locator와 파생 PDF의 preview locator는 서로 구별한다.

새 폴더의 adapter와 validator에 DOM 위치 계약을 추가한다. 기존 PDF 전용 validator의 검사만 느슨하게 하여 HTML 좌표를 꾸며 넣지 않는다. 기존 서비스와 과거 pipeline은 변경하지 않는다.

청킹의 768/1024/2048·overlap96·절/연구 경계·닫힌 표 row block 전략은 유지한다. 새 원문 위치 형식은 source adapter에서 지원한다. 복구로 바뀐 콘텐츠는 다시 청킹하고, 동일한 header+text의 BGE-M3 벡터만 재사용한다. 기존 candidate 및 vectors는 보존하고 새 candidate 버전으로 만든다.

## 검증 표본과 진행 순서

1. 이번3개 HC의 원본 DOM에서 제외된 본문·표·각주가 보존되는지 확인하고 10개 HTML 전체로 넓힌다.
2. PDF의 zero-height 글자·회전·cropbox·부분 영역·같은 글자 여러 위치·특수기호 사례로 좌표 복구/애매한 후보 거절을 검증한다.
3. 큰 DOM 단락, 접힌 section, 긴 list, 다음 쪽 표, 병합 셀, 각주, 중첩 태그, 이미지 포함 원문에 대한 fixture를 추가한다. fixture는 제품 이름이나 이번 페이지 번호와 무관한 구조적 패턴으로 만든다.
4. 현재92문서에 독립 커버리지 audit를 적용해 같은 유형의 누락이 추가로 있는지 확인한다. 모든 본문을 VLM으로 다시 돌리는 작업은 하지 않는다.
5. 보완 결과를 새 extraction/candidate로 검증하고 청킹·BGE·원문 연결 검사를 마무리한다. 기존 서비스 포인터 교체는 별도 단계다.

현재 `ustekinumab_20261014_v1`은 최종 검증 실패 상태이며, 이 설계를 적용하기 전에 완료 release로 표시하지 않는다.
