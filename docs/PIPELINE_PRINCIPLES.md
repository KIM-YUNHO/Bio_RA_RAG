# RA 전처리·RAG 운영 원칙

갱신: 2026-10-11. 사용자가 정한 처리 범위·OCR 역할·평가 방식과 [원문 검토 결과](preprocessing/CASCADE_AND_RAG_SOURCE_REVIEW_2026-10-09.md), [전체 개발 평가](rag/RAG_FULL_SUITE_API_EVAL_2026-10-11.md)를 반영한다. 이 문서는 이후 구현과 실행의 기준이다. 아래 목표를 문서에 기록했다는 사실은 코드 구현·재처리·성능 검증 완료를 뜻하지 않는다. 날짜가 오래된 실험 문서와 충돌하면 이 원칙을 적용하고, 당시 결과는 이력으로 보존한다.

현재 1차 목표는 **전처리 파이프라인 확정과 승인 데이터의 임베딩 완료**다. 전처리에는 원본 출처 확인 → native/일반 OCR → 필요한 복잡 영역 보완 → 표·그림·제목·문맥 메타데이터 연결 → 청킹 → 임베딩·색인 무결성 확인까지 포함한다. 정해 둔 시각에 작업을 끊지 않고 이 기준에 따라 실행한 후 실패를 점검한다. RAG 답변 수정·OpenAI 성능평가·서비스 재시작은 이 목표 이후 별도 단계로 진행한다. 검토 보류와 실패는 전처리 완료·임베딩 성공과 구분해 기록한다.

## 1. 일반화의 기준

- 상품·문서·페이지·질문 ID나 정답 수치를 운영 분기, 청킹, 검색, 답변 규칙에 넣지 않는다. 개발 회귀 테스트에는 실제 실패 사례를 쓸 수 있지만 운영 코드는 관찰 가능한 구조와 출처를 사용한다.
- 상품 카탈로그·기관 범위·시험 별칭의 정상적인 메타데이터 조회와 사례별 정답 하드코딩을 구분한다. 내부 시험 키는 식별용이며 원문 인용으로 사용하지 않는다.
- 기관별 제목 양식이나 용어 사전은 문서 구조를 찾는 보조 신호다. 특정 제목·형식이 없거나 시험/분석 연결이 모호하면 미확정 상태를 남긴다.
- 일반화는 같은 개발 질문에서 점수가 오른 것으로 입증하지 않는다. 코드를 고정한 뒤 개발에 사용하지 않은 문서·질문에 적용하고, 기관·상품·문서 유형별 실패를 공개한다.

## 2. 현재 처리 범위

- 서비스 후보는 SB17·ABP654·CTP43·BMAB1200·BAT2206의 EMA/FDA/HC 문서다. 승인된 명세는 `data/runs/corpus_update_2026-10-09/corpus_plan.json`이며 92문서다.
- 기존 평가 보류 9문서는 계속 제외한다. 일본/PMDA, CTG, sponsor 자료는 현재 서비스 범위에 넣지 않는다. 전처리 엔진 자체를 기관/상품 ID별 전용 파서로 만들지는 않는다.
- `default_search=False`는 기본 검색의 우선순위/선택 정책이다. 승인된 전처리 대상에서 제외하거나 OCR 난이도를 판단하는 신호로 사용하지 않는다.
- 현재 일반 OCR 모델은 Latin 문자용이며 영어·프랑스어가 주 대상이다. 지원하지 않는 문자 체계를 같은 품질로 처리했다고 보고하지 않는다. 언어 지원 부족만으로 문서 전체를 Qwen에 넘기지 않는다.

## 3. OCR과 VLM의 역할

처리 순서는 **검증된 native → 필요한 영역의 일반 PaddleOCR → 결정적인 표 구조 복구 → 남은 복잡 영역의 Qwen**이다.

1. PDF에 글자가 있다는 사실만으로 native를 신뢰하지 않는다. 글꼴 복구·문자 품질·영역 좌표·표 구조를 확인한다. 이미 사용 가능한 native 표/본문은 더 약한 OCR 결과 때문에 보류하거나 VLM 대상으로 격하하지 않는다.
2. 정상 본문·단순 표·단순 삽화의 문자는 일반 PaddleOCR로 읽는다. 검출 모델과 문자 인식 모델을 사용하는 비생성 OCR이며, PaddleOCR-VL을 일반 OCR과 혼동하지 않는다.
3. 전체 페이지나 모든 표·그림을 VLM에 보내지 않는다. crop 단위로 native/일반 OCR 결과, 복구 시도, 미해결 문제와 분기 근거를 기록한다. 페이지는 필요한 문맥을 제공한다.
4. Qwen에는 병합/중첩 셀, 실제로 불규칙한 표 구조, 축·범례·패널 관계가 필요한 그래프, 복잡한 도식처럼 **구조적 복잡성의 양성 근거**가 있는 미해결 영역만 보낸다.
5. 저신뢰 문자, 큰 표, 많은 숫자, 여러 탐지 영역/패널, 읽을 수 있는 라벨만으로 Qwen을 선택하지 않는다. 여러 주사 방법 삽화를 묶었다는 사실은 복잡한 그래프의 근거가 아니다.
6. 빈 입력 양식·단순 명단·본문으로 잘못 탐지된 영역·헤더 조각은 가벼운 복구/재분류를 먼저 한다. 비공개·판독 불가·연속 표 문맥 문제는 더 강한 모델이면 해결된다고 가정하지 않는다.
7. 그림의 문자 인식, 축/범례 역할, 패널 대응, 생성 설명을 구분한다. 곡선·막대의 수치 추정이나 임상적 결론을 그림 설명으로 만들어 내지 않는다.

## 4. 표 구조와 캡션 계약

- 원본 테두리로 완전한 격자가 확인되면 행·열·병합 위치와 셀 ID를 먼저 고정하고 native 문자 좌표와 기존 일반 OCR 토큰을 배치한다. 모두 복원되면 Qwen을 호출하지 않는다. 셀 내부 판독이 남은 경우에도 모델이 기존 셀·숫자·격자를 덮어쓰게 하지 않는다.
- 두 겹 테두리를 빈 행으로 만들지 않는다. 한 열에만 있는 실제 경계도 검사한다. 닫힌 부분 격자를 전체 표로 오인하지 않도록 원래 영역의 문자·토큰 누락을 검사한다. 영역 crop이 외곽선을 잘랐으면 원본 PDF를 제한된 여백으로 다시 렌더해 경계를 확인하며 추가 OCR은 하지 않는다.
- 격자 밖 제목·각주는 좌표와 원문을 따로 보존한다. 옆 열의 누락 문자를 제목·각주로 바꿔 통과시키지 않는다. 빈 칸은 문자/OCR 부재와 테두리를 제외한 원본 내부를 확인한다. 삽화 셀의 문자 라벨과 그림의 의미 검증은 구분한다.
- 새 복잡 표 응답은 논리 행·열 위치, `row_span`/`col_span`, 셀 문자와 상태(`visible`, `blank`, `redacted`, `unreadable`)를 보존한다. 병합 영역을 평평한 빈 칸으로 바꾼 `table-grid-2`는 이전 실행 재현용이며 새 병합 표의 완료 계약이 아니다.
- 범위 초과·겹침·누락 위치·불일치한 행/열 크기·헤더 순서를 검사한다. 빈 칸, 병합 셀이 차지하는 위치, 판독 불가, 비공개를 서로 바꾸지 않는다. 이전 행/페이지의 값을 빈 칸에 채우지 않는다.
- 모델이 제안한 병합 구조는 후보이며, 원본 좌표/격자 등 독립적인 근거로 확인하기 전에는 기하 구조가 검증됐다고 표시하지 않는다. 기존 HTML·native·일반 OCR·VLM 후보와 채택 사유를 각각 보존한다.
- 표 본체, 제목/캡션, 각주, 주변 본문을 분리하고 각 출처 좌표를 연결한다. crop에 함께 들어간 캡션 숫자를 본체의 누락 숫자로 판단하지 않는다. 이를 피하기 위해 실제 본체의 누락 검사를 느슨하게 만들지도 않는다.
- 표/그림 번호만 같다고 연결하지 않는다. 문서 버전·시험/절·좌표·본문 참조·연속성 근거를 확인한다. 이전 페이지 캡션과 이어지는 표 조각도 같은 계약을 적용한다.

## 5. 청킹과 메타데이터

- 토큰 수는 길이 제한이며 의미 경계의 대체물이 아니다. 절·짧은 소제목·시험·주 분석/사후 분석·집단·시점 경계를 보존한다. 제목만 남거나 서로 다른 분석이 한 청크에 섞이지 않게 한다.
- 표 행의 값과 행/열 머리글·단위·비교군·분석집단·각주를 함께 복원할 수 있어야 한다. 긴 표를 나누어도 부모 표와 헤더 연결을 유지한다.
- 문서/버전·기관/상품·물리 페이지·원본 영역·본문 범위·논리 표/그림·문맥 링크·추출 방법·검증 상태를 유지한다. 시험·분석 조건은 원문 근거를 함께 연결하고, 추론한 메타데이터를 원문 문장처럼 인용하지 않는다.
- 보류된 시각 본체를 제목만으로 답변 근거에 다시 포함하지 않는다. 읽을 수 있는 별도 본문/라벨 근거는 해당 출처와 검증 상태로 사용할 수 있다.

## 6. 정답 문맥 선택과 답변

- 페이지를 찾았다는 사실과 정답 표/행을 답변 문맥에 넣었다는 사실을 별도로 측정한다. 같은 페이지의 관련 표와 제목·헤더·각주를 조회하되, 질문과 맞는 시험/분석의 근거를 우선 공급한다.
- 최초 문맥 선택부터 출력·스키마·검증 피드백·제한된 수정 요청의 토큰을 확보한다. 초과한 문맥을 그대로 다시 보내거나 실패를 무제한 재시도하지 않는다. 빠진 근거는 기록한다.
- 수치·문자열의 literal 인용 일치, 출처 링크 유효성, 질문 조건 일치, 답변 완전성은 서로 다른 검사다. 하나가 통과했다고 나머지가 통과한 것으로 표시하지 않는다.
- 시험·투여군·용량·시점·집단·주/사후 분석이 다른 값은 요청한 답처럼 제시하지 않는다. 잘못된 질문 전제는 원문 조건으로 교정하고, 해당 군/값이 없으면 명시한다.
- 용량·경로·초기/유지 간격 등 복수 요청 항목을 각각 근거가 있는 필드로 검증하고 최종 답변에 표시한다. `value`만 보여 주어 검증된 투여 간격이 사라지는 일을 막는다. 검증되지 않은 생성 설명을 표시해 누락을 채우지 않는다.
- 내부 시험 키와 실제 인쇄된 시험명을 구분한다. 조건 인용이 실패하면 인용 검사를 약화하는 대신 원문 연결/모델 출력을 고친다.
- 숫자/표 셀을 모델이 다시 쓰게 하지 않는 추출형 답변에서는 원문 ID만 선택하게 한다. 각 ID의 값·인용·문자 범위는 애플리케이션이 원본 그대로 복사한다. 시험/통계량/용량 등 조건 ID는 실제 인쇄된 역할 후보로 제한하되, 이 후보 자체를 의미 검증 완료로 간주하지 않는다.
- 결과 표의 질문과 무관한 표본 수/평균 농도 열은 확정된 원문 헤더 연결이 있을 때만 값 후보에서 제외한다. 원문 표, 헤더, 출처와 전체 검색 후보는 보존한다. 모델 출력의 임의 시험 귀속은 질문에 시험명이 없더라도 검사한다.
- 입력 예산에 출력 JSON 스키마도 포함한다. 교정 없는 ID 선택은 교정 예약을 사용하지 않으며, 실제 최대 입력/출력 한도는 유지한다. 정답의 여러 지표가 있는 표는 일반 논의 문장보다 먼저 공급한다.
- 형식·문자·숫자 검사만으로 `numeric_evidence_eligible=True`나 임상 의미 검증 완료를 부여하지 않는다. 확인되지 않은 조건과 생성 내용은 표시한다.

## 7. 실행과 재현

- 원본·완료한 추출·기존 평가·보류 명세·frozen 릴리스는 보존한다. 코드/계약이 달라진 실행은 새 출력에 기록한다. 이전 출력의 코드 해시를 새 코드로 바꾸거나 서로 다른 실행을 동일한 완료 결과로 합치지 않는다.
- 작업 입력에는 원본/영역, native 근거, 일반 OCR sidecar, 현재 선택 표현, 문맥, 라우팅/응답 계약 버전을 연결한다. 논리 그림 그룹은 부모뿐 아니라 구성 영역의 근거도 입력 해시에 포함한다.
- 계약/출처가 다른 작업을 기존 worker에 그대로 넘기지 않는다. 변경된 규칙은 모델 호출 없이 회귀·분기·입력 바인딩 검사부터 통과시킨다.
- 반복은 실패 원인이나 변경된 입력이 있을 때만 한다. 완료한 일반 OCR 996건을 다시 수행하거나 이전 199개 큐를 통째로 Qwen에 보내지 않는다. 이 수치는 현재 실행 이력이며 일반성의 증거가 아니다.
- 전처리 완료, 인덱스 생성, 답변 검증, 서비스 반영을 별도 상태로 보고한다. 아직 전처리가 진행 중인 후보를 최종 성능 개선으로 보고하지 않는다.

## 8. 평가와 일반화 검증

- RAG 질문 해석·답변 생성 평가는 OpenAI API `gpt-4o-mini`로 한다. 가용성 확인 호출은 하지 않는다. 실제 시도/캐시 재사용/토큰/지연/오류를 기록하고 KST 일일 장부와 실행 상한을 적용한다. 실행 상한을 계정의 실제 일일 잔여량이라고 말하지 않는다.
- 먼저 원문과 기존 청크로 검색/문맥 손실을 검사한다. 이미 정확한 표가 있는데 문맥에서 빠진 실패를 OCR 재작업으로 해결하려 하지 않는다.

## 14. 실제 후속 API 평가와 원문 후보 제한 — 2026-10-10

다중 비교의 누락 조합이 실제 표에 공급된 경우에만 같은 원문·스키마로 최대 한 번 교정한다. 기존 검증된 사실을 보존하고 추가 응답의 검증된 누락 슬롯만 합친다. 남은 누락은 부분 답변이며 임상 의미 인증 상태를 자동 승격하지 않는다.

다음 구현은 [현재 전략과 공통 수정 설계](rag/RAG_GENERAL_STRATEGY_2026-10-11.md)를 기준으로 한다. 이는 새 동작의 적용·성능 검증 완료 기록이 아니다.

- 분석 조건은 논리적 조합으로, 비교는 방향을 가진 쌍으로, 단위/집단/시점/사건은 해당 값의 타입과 범위로 검증한다. 조건 단어가 하나 있다는 이유로 요구 조합 전체가 맞다고 표시하지 않는다.
- 명시적 Part와 공동 방법 연결을 사용하되 대상/분석 전환에서 상속을 닫는다. 요청에 없는 차원을 무조건 강제하지 않는다. 조건 불일치·미확정·일치를 분리한다.
- 모델이 선언한 exact/answered 대신 검증된 요구 충족으로 상태를 계산한다. 원문에 있는 숫자라도 다른 행의 값이면 제외한다. 미확인 요청 필드를 공개하고, 상위 검색 문맥 부재를 문서 전체의 미보고로 단정하지 않는다.
- 정상 문장 답변과 현재 정답 유지도 함께 검사한다. 불필요한 보류를 늘려 안전 지표만 개선하지 않는다. 개별 사례는 회귀에 사용하고 운영 분기는 구조·관계·요구 조건에만 둔다.
- 순서는 독립 요구/근거 계약 → 기존 표·본문·제목의 관계 sidecar → 공통 조회·검증·표시 → 검색 실패 보완 → 작은 API 회귀와 고정 코드 새 질문 평가다. 임베딩 입력이 같으면 벡터를 재사용하며, 실제 바뀐 표현만 다시 색인한다. 원문 구조 오류가 확인된 일부 영역만 전처리를 보완한다.

## 16. 새 질문 진단 후 구조·적용 범위 원칙 — 2026-10-11

[새 질문 진단](rag/RAG_TRANSFER_DIAGNOSIS_2026-10-11.md)은 후보의 일반화 완료 기준을 충족하지 못했다. 노출 후 수정한 문항은 개발 회귀로 전환하며 같은 평가에서 미노출 성능으로 다시 집계하지 않는다. 검색 페이지 hit 상승·회귀 통과·없는 값 보류만으로 답변 품질 상승을 선언하지 않는다.

- 제형·준비 상태·사건은 값 자체의 문장/명시적 범위로 확인한다. 희석 주입액, 프리필드 시린지, 개별 바이알을 서로 대체하지 않는다. 화학·물리적 안정성과 미생물학적 사용 지침도 관계를 보존한다. 금기 질문은 실제 금기 predicate/명시적 금기 절을 요구하며 경고의 교차 참조를 대신 쓰지 않는다.
- 숫자가 포함된 범주도 원문 문법으로 구분한다. 체중 경계 범주는 같은 행 용량의 조건이고 결과 값이 아니다. 누락된 인쇄 구간이 있으면 완전 답변으로 표시하지 않는다. 값/단위/CI 수준/마진/시점의 역할을 표 또는 자체 문장에서 확인한다.
- 여러 페이지 표의 연결이 미확정이어도 자체 헤더와 닫힌 물리적 행 그룹이 검증되면 그 부분만 검색 후보로 사용할 수 있다. 경계의 미완성 그룹은 제외 상태와 원문 위치를 보존한다. cross-page 연결, 수치 정확도, 임상 의미를 동시에 승인한 것으로 표시하지 않는다.
- 청킹은 헤더를 원문 그대로 반복하고 병합 셀·닫힌 행 블록을 자르지 않는다. 그룹 자체가 예산보다 크면 보류한다. OCR/HTML 형식·숫자 bag 일치만으로 열 연결이 맞다고 판단하지 않는다.
- PDF 네이티브 글자와 선으로 충분한 영역은 모델을 호출하지 않는다. 일반 영역은 가벼운 OCR, 복잡한 행/열 연결이 미해결인 제한 ROI만 Qwen 순서를 유지한다. 재색인은 실제 임베딩 입력이 바뀐 부분에 한한다.
- 답변은 관계를 보존하는 최소 원문 문장을 우선한다. 더 큰 부모 문단이 있다는 이유로 다른 사건의 조건을 값에 붙이지 않는다. 관계 미확정인 단독 수치를 승인하는 대신 요청 누락을 표시한다.

## 17. 인쇄 역할 기반 추출과 반복 계산 제한 — 2026-10-11

- 명시적으로 나열된 기술 PK 통계 요청만 제한 계약으로 해석한다. 단순 목록은 평균·SD·중앙값·최소·최대·범위를 지원하고 군/용량별 필드를 구분한다. 상관된 절·선택/제외 조건·미지원 체중 조건을 삭제하여 단순 요청으로 바꾸지 않는다. 전체 임상 질문 해석이 승인됐다고 표시하지 않는다.
- 표 결과의 제목·군·통계량·단위는 값 자체의 인쇄된 행·열·닫힌 블록에서 만든다. endpoint 표기 속 `max`는 최대 통계량이 아니다. 모델이 만든 항목명이나 주변 조건으로 자체 셀의 역할을 덮어쓰지 않는다.
- 원문 역할·독립 시험 연결·요청 슬롯이 유일하고 상충하는 값이 없을 때만 원문 전체 셀을 결정적으로 추출할 수 있다. 복합 셀은 분해하지 않는다. 미확정 관계·잘못된 조건·누락 슬롯을 자동으로 채우지 않는다. 동일한 값의 서로 다른 군은 별도 출처로 남긴다.
- 본문은 수치·단위·조건을 보존한 전체 문장으로 반환한다. 인접 용량·분석군을 통계량 등 다른 차원의 조건으로 붙이지 않는다. 여러 endpoint의 각 숫자 대응을 별도 확정했다고 표시하지 않는다.
- 속도 개선은 동일 표현의 순수 계산 재사용으로 한다. source text와 출처가 달라지면 prompt 캐시를 사용하지 않는다. 파싱 결과는 호출자별 복사하고, 범위/경계 검증은 유지한다. 캐시와 추가 문맥 예산은 유한하게 둔다.
- 국소 API 회귀와 저장 선택 재검증을 구분한다. 한 코드의 전체 유효 개발 평가와 이후 코드 고정 상태의 새 질문을 통과하기 전 안정적 일반화 개선이나 서비스 채택을 선언하지 않는다. [구현·검증 기록](rag/RAG_PRINTED_ROLE_PLAN_2026-10-11.md)에 현재 상태를 남긴다.

## 18. 필드·각주 적용과 정답 문맥 — 2026-10-11

- 적격 조건은 각 필드의 자체 수치 경계·단위·집단 조건을 보존한 전체 원문으로 공급한다. 닫힌 inclusion 범위, 유일한 필드 조합, 독립 시험 연결이 모두 확인된 경우만 자동 추출한다. 다른 필드의 숫자나 P-value로 빈 항목을 채우지 않는다.
- ADA/NAb, baseline/boosted/방문별/전체 기간을 해당 값의 헤더·문장에 연결한다. 헤더/assay 제목을 발생률 값으로 선택하지 않는다. 대조약의 지역과 일반명은 인쇄된 동일 군 헤더와 해당 상품의 신원 별칭에서 확인하며 결과는 카탈로그에서 가져오지 않는다.
- 병합된 비율/CI 셀은 실제 덮는 Test·Reference 행과 각주를 함께 확인한다. 표 전체의 여러 비교 각주를 모든 셀에 배정하지 않는다. 군/표/기호/원문 범위가 모순되거나 유일하지 않으면 미확정이다. 숫자만 맞추거나 비율을 역산하지 않는다.
- 닫힌 결과 블록의 통계량이 이전 열의 통계량을 대체할 수 있다. endpoint/단위 등 다른 차원은 그대로 자체 근거를 검사한다. 명시적 GMR+90% CI 헤더와 완전한 estimate(bounds) 셀이 있어야 두 필드를 공급하며 전체 셀을 그대로 보존한다. mean(SD)·신뢰수준 미표시 CI를 같은 계약으로 해석하지 않는다.
- 모델의 항목명/조건은 원문 역할을 덮지 않는다. 유일하게 연결된 원문 endpoint·통계량·비교·분석 제목으로 표시하고 모델 원본과 관계 증거는 감사 이력에 남긴다. 요청에 없는 primary 단어를 강제하지 않으며, 명시적 주분석 요구는 그대로 유지한다. 실제 분석 제목을 주분석 인증으로 승격하지 않는다.
- 해당 셀에 명시적으로 연결된 ADA 양성/음성 집단·체중 구간·단백질 보정·사후 분석은 요청하지 않은 전체 결과의 대용이 아니다. baseline-weight 공변량과 체중 하위집단을 구분한다. 요청한 조건의 unknown과 다른 명시적 범위의 mismatch를 분리하며 주변에 있는 단어만으로 범위를 축소하지 않는다.
- GMR/CI 자동 선택은 원질문의 제한 문법에서 모든 역할을 설명할 수 있고 각 요청에 유일한 원문 전체 셀과 독립 시험/분석 근거가 있을 때만 한다. 알 수 없는 조건·추가 필드를 삭제해 요청을 완성하지 않는다. 같은 값의 다른 원문 위치는 모호하며 한 복합 셀로 여러 필드를 공급해도 한 번만 반환한다.
- 페이지 검색·페이지 내 후보·최종 문맥 큐·표 토큰 할당에 동일한 제한 역할 신호를 적용한다. 필드/endpoint 일치와 일부 조건 unknown은 검색 후보가 될 수 있고, 완전한 AND 지지가 더 강한 신호다. 검색 신호는 답변 조건 승인과 구분한다. 사용자/상품/기관/보류 경계와 실제 최종 토큰 상한은 유지한다.
- 이 변경의 구현·실제 API 판정·저장 재검증·문맥 공급 진단·남은 전이 검증은 [필드·문맥 보완 기록](rag/RAG_SOURCE_FIELDS_UPDATE_2026-10-11.md)에 별도 실행으로 남긴다.


## 19. 새 질문 실패 이후 공통 근거 단위와 부분 계약 — 2026-10-11

기존 개발49/69와 사전 고정 새 질문2/15·통제2/3을 분리한다. 후자는 안정적 일반화 기준 실패이며 노출된18문항은 개발 회귀로 전환한다. [새 질문 원문 판정](rag/RAG_PROSPECTIVE_SOURCE_API_EVAL_2026-10-11.md)을 보존하고 실패 문항을 제외하지 않는다.

- 원문 값은 전체 복합 셀 또는 최소 온전한 양적 문장으로 유지한다. 인원/비율, 용량군, 범위/CI를 부분 숫자로 나누어 임의 항목명에 붙이지 않는다. 값이 같아도 다른 위치/군은 별도 출처다.
- 해당 값에 물리적으로 연결된 행·열 헤더를 직접 표시한다. 모델의 항목명은 미확정 군/제형/경로/사건 관계를 승인하는 근거가 아니다. 구조 정합성과 임상 의미 승인을 구분한다.
- 전체 질문 해석이 미완성이어도 명시적으로 확정된 비교 쌍·투여 경로와 충돌하는 원문은 제외한다. 제외/상관 조건을 원질문에서 삭제하지 않으며 부분 계약으로 자동 완료를 승인하지 않는다.
- 제제/용기의 함량과 투여량을 구별한다. 한국어 원질문의 숫자 역할을 기준으로 검사하고 번역의 추가/누락으로 필수 조건을 바꾸지 않는다.
- 화학·물리적 안정성, 미생물학적 사용 지침, 농도는 같은 제형 아래 별도 요청 필드다. 한 필드의 predicate를 AND로 요청한 다른 필드에 강제하지 않는다. 희석한/희석된/희석 후도 같은 준비 상태로 인식한다.
- 군별 양성률은 실제 analyte·군과 독립 시험 연결로 누락을 검사한다. 한 군만 반환한 answered로 전체 완료를 표시하지 않으며 없는 결과를 계산/추가하지 않는다.
- mismatch와 unknown을 구별한다. 미확정 근거를 모두 삭제해 정상 답변을 잃는 회귀도 검사한다. 긍정 관계의 원문 인용 요청에 그 관계가 확인되지 않은 인용을 확정 답변으로 제시하지 않는다.

## 20. 기본 원문 단위·목록 의존성·문서 내 시험 식별자 — 2026-10-11

[새 혼합 질문 평가](rag/RAG_QUANTITY_TRANSFER_API_EVAL_2026-10-11.md)의 2/6 정답·통제2/2는 사전 기준에 미달했다. 숫자의 존재만 확인하면 함량이 투여량으로 표시되거나 경계·비교군 관계가 변형된다. 후속 [노출 개발 4문항 API](rag/RAG_SOURCE_ONLY_UPDATE_2026-10-11.md)는 3/4 정답이며 다른 시험의 표 선택 한 건이 남았다. 이 수치를 기존 전체49/69 또는 미노출 일반화 점수와 합치지 않는다.

- 기본 선택 단위는 최소 온전한 원문 문장·표 셀이다. 독립적인 인쇄 역할이 연결된 PK·인원·양성률·투여량·소아 적응증 연령 등 제한 계약만 단독 수치를 허용한다. 범위의 일부나 제제 성분의 mg가 투여량이 되지 않는다. 같은 값의 다른 군·위치를 합치지 않으며 같은 원문 셀의 반복 반환만 제거한다.
- 같은 권장 투여량이 초기·유지 구문에 반복돼도 반복 수만으로 역할을 부정하지 않는다. 해당 수치 위치의 추천 용량/후속 정기 투여 구문을 직접 확인한다. 같은 숫자의 성분 함량은 이 구문을 상속하지 않으며 서로 다른 질량군은 온전한 문장으로 유지한다. [정상 역할 보존 검증](rag/RAG_REGIMEN_WHOLE_SOURCE_2026-10-11.md)은 저장 재검증이며 새 API 정확도가 아니다.
- 검증되지 않은 모델의 한국어 항목명·조건은 사실 표시의 근거가 아니다. 원문 관계가 불명확하면 온전한 인용으로 표시하고 실제 연결된 표 헤더·목록 설명만 붙인다. 원문 인용·구조 정합성·요청 충족·임상 의미 승인은 구분한다. 주변 경고까지 길게 인용되는 문제는 별도 품질 결함으로 남긴다.
- 목록 값은 콜론으로 끝나는 원문 설명과 연속 목록의 관계를 유지한다. 문맥 선택은 그 설명과 선택한 항목까지의 연속 목록을 같은 토큰 예산 안에 포함한다. 원래 빈 구간·새 문단·표 경계를 넘어 설명을 상속하지 않는다. 과거 저장 문맥에서 빠진 설명을 재생 시 만들어 넣지 않는다.
- 원질문의 문서 내 시험 식별자는 등록된 PK 시험과 별도로 원문 위치를 보존한다. 값 자체의 문장·정렬된 헤더·바로 연결된 실제 표 제목에 다른 식별자가 명시되면 대체 결과로 쓰지 않는다. 같은 문서·페이지·메타데이터 제목이나 모델 조건만으로 시험 귀속을 인정하지 않는다.
- 요청한 여러 시험은 각자의 원문이 필요하다. 하나의 시험만 확인했거나 귀속이 미확정인 관련 인용은 부분 답변이다. 제외·대안 등 미지원 논리를 식별자 목록의 AND로 축소하지 않는다. 시험 식별자 일치가 질환·사건·분석·전체 요청의 의미 승인을 대신하지 않는다.
- API는 코드·문항·판정 기준·호출 상한을 고정한 차수에서 실행한다. 새로운 원문 숫자나 정답을 운영 규칙에 넣지 않는다. 저장 선택 재검증의 차단·유지는 새 답변 정확도가 아니다. 기존 전체 개발·노출 문항 수리·코드 고정 후 새 질문 전이를 각각 보고하며 안정적 전이 검증 전 서비스 채택을 선언하지 않는다.

## 21. 문서 전이 경계·공통 요청 집계 — 2026-10-11

[문서 노출 조사와 selector24 공통화](rag/RAG_DOCUMENT_TRANSFER_AND_COMMON_COVERAGE_2026-10-11.md)는 회귀860개·저장104개 동작 유지 기록이다. 새 답변 정확도나 새 문서 일반화 측정이 아니다. 승인92개 중 저장 개발 문맥의 노출을 확인한 문서는52개이며 핵심 평가보고서·제품정보31개 모두 포함한다. 노출 기록이 식별되지 않은40개도 미노출이라고 자동 승인하지 않는다.

- 새 문서는 정해진 전처리·색인·품질 검사를 거치는 것이 기본이다. 기존 구조를 처리하기 위해 문서마다 정답 규칙을 추가하지 않는다. 새로운 구조 유형은 공통 추출 계약의 결함으로 진단하며, 원문 공급·관계·요구·선택·표시 실패를 구분한다.
- 문서 단위 전이는 질문의 새로움과 구분한다. 개정본·상품명만 다른 공통 형식·개발 문맥 노출을 확인한 뒤 평가 자료를 고정한다. 기존 핵심 문서를 다시 나눠 미노출 문서라고 부르지 않는다. 보류9개를 개발·서비스로 편입하지 않는다.
- 공통 요청 충족 집계는 필드마다 한 원문 단위가 전체 AND를 지지하는지를 확인한다. 다른 셀의 조건 조각을 합치지 않으며, 모델/상위 상태가 하위 미확정·충돌을 덮지 않는다. 지원 출처 ID와 누락 요청을 함께 보존한다.
- 미지원 조건과 불완전한 질문 해석을 삭제해 `answered`로 만들지 않는다. 컴파일된 요청 충족, 질문 전체 해석, 원문 구조, 임상 의미 인증을 따로 보고한다. 특정 문항의 조건을 다른 요청 필드에 강제하는 기존 검사도 같은 계약으로 순차 이동한다.
- 새 문서 일반화 성능은 독립 승인 문서군에서 코드 고정 후 평가한다. 평가 중 수정하면 해당 자료는 개발로 전환하며 실패를 분모에서 제외하지 않는다. 정확도·허위 답변·정상 근거의 과잉 보류와 문서군별 범위를 함께 평가한다.

## 22. 효과성 우선·반복 수정과 호출 제한 — 2026-10-11

[효과성 재검토](rag/RAG_EFFECTIVENESS_REVIEW_2026-10-11.md)에 따라 좁은 필드 목록을 모든 질문의 필수 통과 조건으로 확대하지 않는다. 요청별 누락·원문 연결 검사는 유지하지만 필드 미등록을 근거 부재로 취급하지 않는다. 미해석 요청을 삭제해 전체 완료로 만들지 않는다.

- 저장 평가에서 정답 원문의 추출·검색·최종 문맥 공급·선택·검증·표시 실패를 먼저 나눈다. 병목 확인 전에는 새 API를 호출하지 않는다.
- 개별 질문의 정답을 보고 필드/정규식을 계속 추가하지 않는다. 공통 변경이 여러 문서·주제에 효과를 갖는지와 기존 정상 답변의 손실을 확인한다.
- 회귀 통과 수와 API 호출 횟수를 성능 향상으로 보고하지 않는다. 완전 정답·오답·누락·과잉 보류·비용을 함께 본다.
- 개선 근거가 확인된 코드·문항·판정 기준·상한을 고정하고 제한 API 평가를 한 번 실행한다. 같은 문항을 통과할 때까지 수정·호출하지 않는다.
- 검색/문맥 공급 누락이 병목일 때만 기존 하이브리드·리랭커 후보를 비교한다. 이미 공급된 원문의 의미·표시 오류는 검색 확대의 근거가 아니다.
