## 2026-10-16 01:55 KST — 계획기가 질문을 읽고, 체크리스트로 생성, 문서 목록·correspondence 기본 검색

main 반영: `8568f8c`(planner-facets), `f4dc6da`(checklist-ask). 서비스(8885) 재시작 완료.

### 원칙

- 질문의 **의미 판단**(무엇을 묻는지, 어느 기관인지, 어떤 문서가 필요한지)은 계획 LLM이 한다.
- 코드는 **고유명사와 원문 사실만 확인**한다. 제품명이 레지스트리에 있는지, 계획기가 옮겨 적은 단어(기관명, 군·구간, endpoint, Part 번호)가 질문에 실제로 있는지, 답변 숫자·날짜가 인용한 원문에 있는지를 본다.
- 계획기의 해석은 **답변의 틀이 아니라 체크리스트**로 쓴다. 틀로 고정하면 정규식이든 LLM이든 같은 실패(칸 부족, 누락 시 답할 자리 없음)가 생긴다.

### 1. 체크리스트란

계획기가 읽은 "질문이 요구하는 것" 목록을, 생성 LLM에게 "빠뜨리지 말 것"으로 건네는 메모다.

계획기는 작업마다 다음을 출력한다.
- `answer_facets`: 요청한 사실의 종류(닫힌 선택지: dose_route, dosing_schedule, table_statistics, design, eligibility, reference_selection, analytical_bridge, document_status_scope, calculation 등)
- `items`: 따로 답해야 할 군·구간·시점(질문 원문 그대로; 예: "US ustekinumab군", "체중 55 kg 이하")
- `ask`: 그 facet이 이 질문에서 답해야 할 내용을 질문의 용어로 다시 쓴 한 줄(예: "피하 유지 투여의 시작 시점과 반복 간격")

코드는 항목이 질문에 실제로 있는지만 확인하고, 생성 LLM 입력에 이렇게 넣는다.

```
answer_checklist:
- CTP43 | 체중 구간별 정맥 유도 용량과 바이알 수 | 체중 55 kg 이하
- CTP43 | 체중 구간별 정맥 유도 용량과 바이알 수 | 55 kg 초과 85 kg 이하
- CTP43 | 체중 구간별 정맥 유도 용량과 바이알 수 | 85 kg 초과
- CTP43 | 피하 유지 투여 일정
```

생성 LLM은 각 줄을 claim(근거 인용이 달린 답변 문장)으로 답하거나 gap으로 적는다. claim 수는 기존 상한 안에서 자유이고, 목록에 없는 내용도 원 질문을 보고 답한다. 답변 뒤 완료 판정도 같은 facet을 쓴다(상태 표시만 바꾸고 claim을 지우지 않는다).

이전 "요구 항목 칸" 방식(줄마다 claim 1개)은 `RA_REQUIREMENT_MODE=slots`로만 남겼다.

### 3. 검색 이후 단계에 미칠 영향과 LLM 입력 단계 처리

현재 흐름(`rag/ra_retrieval.py`의 `retrieve`, `context`):
- 검색은 작업 × 제품 × 기관 조합(그룹)마다 상위 후보를 뽑는다. 계획기가 고른 문서 역할은 순위 가산점이다.
- 패킹은 모든 그룹의 1위, 그다음 2위… 순으로 입력 예산이 찰 때까지 돌아가며 채운다.
- 재순위는 꺼져 있다. 재순위 모델은 로컬 cross-encoder(`BAAI/bge-reranker-v2-m3`, `rag/rerank.py`)라 API 비용은 없고 로컬 계산 시간만 든다.
- 체크리스트는 생성 지시에만 쓰이고, 어떤 근거를 넣을지는 고르지 않는다.

오늘 변경의 영향:
1. correspondence가 들어와 그룹마다 후보가 늘었다. 보충신청 허가서한이 여러 개인 제품은 원 허가서한과 순위를 다툰다.
2. 역할 가산점이 계획기 선택에 달려 있어, 역할 선택이 흔들리면 그룹 안 순위도 흔들린다(Q5 2회차).
3. 역할이 3개로 늘면 가산점이 분산된다(Q1 캐나다 결정 요약서가 밀린 원인으로 추정).
4. 재순위를 켜도 지금은 계획기 검색어 기준이라 체크리스트와 맞물리지 않는다.

LLM 입력 단계에서 할 수 있는 방법:

| 방법 | 내용 |
|---|---|
| A. 체크리스트 기준 패킹 | 체크리스트 항목 × 제품 × 기관마다 가장 맞는 근거 1개를 먼저 확보하고, 남은 예산을 지금처럼 돌아가며 채움 |
| B. 재순위 질의 = ask | 로컬 재순위 모델로 그룹마다 계획기의 ask 기준으로 후보를 재정렬(후보 수를 제한해 지연 관리) |
| C. 근거를 단위별로 정리해 제시 | 근거를 제품 × 기관 단위로 묶고 문서 종류·날짜를 머리에 표시 |
| D. 중복 문서 접기 | 같은 내용의 허가서한·라벨 판본을 하나로(옵션은 있으나 꺼짐) |

진행: A 효과부터 측정한다(저장된 계획으로 검색·패킹만 다시 해서, LLM 입력 근거에 정답 값이 들어가는지 비교; API 비용 없음).
