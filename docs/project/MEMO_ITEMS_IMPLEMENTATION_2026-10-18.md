파이프라인 이름은 **`[공개자료 재현 v1] SB17 IV FcRn 검토`**다. 같은 데모를 로컬 8775 서비스에서도 볼 수 있다.

1. `공개자료 재현` 메모를 연다. 관측 결과 98–102%, 사례 유사성 범위 107–127%, CHMP의 해당 제품 판단이 별도 항목이다. 각 항목의 `항목 원문 보기`로 실제 PDF p.35를 확인한다.
2. `직접 메모` 세 개는 합성 내부 의견·후속 조치·기관 질문이다. 실제 기업의 발언·시험·납기·기관 답변과 구분하는 문구를 넣었다.
3. `업무별 항목 보기`에서 결과 검토 / 협력사 미팅 준비 / 기관 질문 준비를 선택한다. 시험·쟁점으로 표시 대상을 좁힐 수 있다. **현재는 유형별 순서를 달리해 모으는 내부 검토 화면**이다. 질문별 근거 선정·새 코멘트 작성·외부 전달본 생성은 아직 하지 않는다.
4. 메모 `수정`에서 유형·시험 대상·자료 성격·성숙도·유효성·추가 의견을 바꿀 수 있다. 원 주장·발언 주체·인용은 보존한다. 사용자 분류와 자료 상태는 미검증 입력으로 표시한다.

원본 과학 자료는 SHA-256 `fea275487bb971962201b77aec3d2e12cee7d545be026b378f1980fa272f6e76`인 Pyzchiva EPAR p.35다. 실험 자료의 세부 상태는 공개되지 않았으므로 `not_disclosed`로 유지했다. 합성 코멘트는 [재구성 문서](../demo/internal_pipeline_v1/02_SOURCE_DOCUMENTS.md)의 D06·D08·D09에 근거한다.

## 구현한 동작

| 부분 | 현재 동작 |
|---|---|
| RAG 답변 저장 | 주장별로 저장 항목 선택. 서버가 보관 보고서에서 본문·인용·역할·기존 모델 근거 검토 정보를 다시 읽음 |
| 정보 단위 | 미분류 / 사실·결과 / 적용 기준 / 의견·해석 / 결정 / 후속 조치 / 미해결 질문 |
| 추가 정리 | 시험·쟁점 이름, 관측·예상·계획 등의 자료 성격, 성숙도, 시험 유효성, 별도 추가 의견 |
| 출처 | 주장 ID, 원 인용문과 위치, 문서·버전·페이지, 보고서 해시, 발언 주체 보존 |
| 미공개 상태 | 분류만으로 미공개 시험의 유효성·성숙도를 확정하지 않음. 사용자가 입력한 상태는 인증과 구분 |
| 기존 메모 | 읽기만으로 변경하지 않음. `원 답변에서 항목 불러오기`가 저장 당시 보고서 해시를 확인한 뒤 명시적으로 변환. 수정 본문·보관 여부·이력 보존 |
| 수정 충돌 | 기존 revision 검사 유지. RAG 원 주장은 읽기 전용이고 메모 본문·추가 의견과 분리 |
| 업무 보기 | 보관하지 않은 메모의 항목만 모음. 내부 초안 표시. 유형별 정렬·시험/쟁점 필터·원 메모/원문 이동 |
| 저장 | 기존 프로젝트 JSON에 `items`를 추가. PostgreSQL·파일 저장 모두 지원. 이번 단계에 별도 DB 테이블/스키마 변경 없음 |

원 보고서가 주장을 제공하지 않는 과거 메모·근거 텍스트를 임의로 쪼개거나 사실로 승격하지 않는다. 기존 직접 메모는 자동 항목화하지 않으며, 새 직접 메모부터 하나의 항목으로 저장한다. 현재 시험·쟁점은 자유 입력 문자열이므로 동일 실험 식별자와 동의어를 통합한 상태는 아니다.

## 실제 실행한 확인

- Python 테스트 **58개 통과**: 새 항목·출처·선택 저장·잘못된 변경 거부·원문/추가 의견 분리·기존 메모 변환·충돌·두 HTTP 서버·기존 UI 계약·PostgreSQL 저장·실제 PDF 재현.

- 격리 HTTP fixture의 DOM 통합 검사 통과: 분류·시험 대상 저장, 유형/대상 필터, 빈 항목 선택 거부, 업무 보기, 원문 이동, 새로고침, 직접 프로젝트/단계 링크.
- 실제 8885 서비스의 **읽기 전용 DOM 검사 통과**: 메모 4개·항목 6개, 공개/합성 표시, 실제 PDF 뷰어, 세 업무 보기, 원 메모 이동. POST·모델 호출 없음.
- 8885·8775 서비스 재시작 후 정상 준비 상태 확인. 기존 프로젝트 본문 전체를 배포 전 백업과 대조해 동일함을 확인했다. 새 데모 프로젝트만 추가했다. 원본 p.35·하이라이트 7개 확인.

## 다음 검증 범위

1. 시험·제형·제품 식별자와 항목 간 연결을 정리한다. 현재 `subject`는 자유 입력이며 기준↔관측 결과 참조, 충돌·폐기·대체 관계는 아직 없다.
2. [REPLAY 문서 9개](../demo/internal_pipeline_v1/02_SOURCE_DOCUMENTS.md)를 독립 입력으로 적재하고 문서 종류·공급 범위·공유 범위·버전을 연결한다. 이번 메모 데모가 9개 문서 전체의 적재를 뜻하지 않는다.
3. 사용자 업무 질문에 맞게 저장 항목을 검색·선정해 모델 문맥에 넣는 연결을 구현한다. 현재 일반 RAG 질의는 저장 메모를 자동 재검색하지 않는다.
4. [공개 개발용 정답 12개](../demo/internal_pipeline_v1/06_GOLD_CASES.md)에 대해 T1/T3 입력 허용 목록을 강제하고 실제 검색·답변·업무 산출물을 실행·채점한다. 정답/예상 산출물은 모델 입력에서 제외한다.
5. 협력사 전달용 산출물은 문서/항목별 공유 규칙으로 내용을 걸러야 한다. 현재 업무별 보기는 내부용이며 외부 전달본으로 분류하거나 전송하지 않는다.

**58개 구현 테스트 통과와 12개 RAG 정답셋 정확도는 다른 결과다.** 정답셋은 여전히 `not_run`이며 수치·의미 정확도 점수를 주장하지 않는다.
