## 발표 방향 확정 사항

- 도입부는 **RA 업무의 주요 pain point**를 먼저 설명한다. 자료 분산, 비교 조건 정리, 심사 경위·적용 범위 해석, 원문 검수, 내부 공유·기록 축적의 다섯 항목이다.
- 문서 파싱·표·청킹 문제는 그다음 장에서 업무상의 어려움을 만드는 기술적 원인으로 연결한다.
- **메인 LLM 선정은 GPT-5.6 Luna (`gpt-5.6-luna`)**다. 질문 해석·계획, 답변 생성, 내부 주장 검토를 담당한다. 수집 요청 해석용 gpt-4o-mini는 보조 역할로 구분한다.
- 모델 선정 사실은 사용자 확인을 반영한다. 선정 이유를 설명할 때 타 LLM 대비 우월성·순위·비용 수치를 새로 만들지 않고, 담당 업무와 실제 평가 구성으로 설명한다.

## 2. 발표에 활용하기 좋은 문제 해결 사례

### A. 전처리: 모델 추가보다 선별과 후보 검증이 중요했다

- 문제: 빠른 기본 추출에서 누락 표·그림과 불완전한 표 구조가 발견됐다.
- 접근: 기본 추출에 독립 영역 점검을 붙이고 필요한 표만 PaddleOCR-VL로 다시 전사했다.
- 결과: 최종 G′→H 비교에서 고정 셀 79/90→88/90, 표 영역 16/18→18/18, 그림 3/4→4/4. 고정 개발 표본 15쪽이다.
- 선택: Qwen 표 보강은 이 비교에서 채택 후 개선이 없었으므로 H 기본 경로에 넣지 않았다. 모델군 전체의 우열을 의미하지 않는다.
- 발표에 쓸 문장: **“기본 추출을 유지하면서 누락·불완전 표를 선별하고, 검증한 후보만 반영했습니다.”**
- 근거: [전처리 최종 선정](../preprocessing/FINAL_PREPROCESSING_DECISION_2026-10-14.md).

### B. 리랭커: 후보를 늘린 실험은 실패했고, 사실별 질의와 순위 결합이 효과적이었다

- 문제: 단순 리랭커·후보 확대는 오프라인 근거 recall을 높여도 입력 예산과 생성 혼동 때문에 최종 답변 점수를 떨어뜨렸다.
- 실패 관측: 후보 16개 + ask 리랭커 실험에서 답변 점수는 기준 278점에서 262점으로 낮아져 반영하지 않았다.
- 수정: 제품·기관·요청 사실을 리랭커 질의에 넣고, 하이브리드 순위와 리랭커 순위를 RRF로 결합했다. 후보는 그룹당 8개를 유지했다.
- 결과: 개발 검색 recall@8 0.715→0.804, 29문항×2회 답변 점수 278/384→311/384. 전체 처리 중앙값은 해당 비교에서 17.5→18.1초, 최대는 52→75초였다.
- 발표에 쓸 문장: **“리랭커의 입력을 명확히 하고 기존 검색 순위를 함께 활용했을 때 최종 답변 개선으로 이어졌습니다.”**
- 해석: 계획기의 사실 ask와 검색 구성도 함께 바뀐 실험이다. 리랭커 모델만의 독립 효과로 설명하지 않는다. 지연은 당시 실행 조건의 관측값이다.
- 근거: [질문 처리 기록 03:14·07:42·08:12·09:37](../RA_QUERY_HANDLING_LOG.md).

### C. 인용 검증: 원문 위치가 맞아도 잘못된 시험을 연결할 수 있었다

- 문제: 문서 자체의 잘못된 표 참조 번호, 이전 시험 제목의 상속 때문에 다른 시험의 표가 문맥에 포함됐다.
- 감사: 청크·출처 구조 검사 위반 0건과 별개로, 캡션 시험번호와 상속 제목이 충돌하는 표 청크 15개가 확인됐다.
- 수정: 명시 시험·Part 충돌을 차단하고 충돌하는 상속 제목을 공급 문맥에서 제외했다.
- 결과: 고정 청크 재현에서 잘못된 연결 차단과 일부 누락 표 공급을 확인했다. 새 전체 질문 생성 성능을 평가한 결과는 아니다.
- 발표에 쓸 문장: **“인용의 존재뿐 아니라 시험·군·조건의 관계를 확인하도록 검증을 보강했습니다.”**
- 근거: [문맥 연결 감사](../rag/CONTEXT_LINK_AUDIT_2026-10-16.md), [수정·재현 검증](../rag/CONTEXT_LINK_FIX_2026-10-16.md).

본문에서 사례를 하나만 자세히 설명한다면 B를 추천한다. 검색 지표와 최종 답변을 함께 봐야 하는 이유를 보여주며, 전처리는 4단계 흐름과 대표 수치로 압축할 수 있다.
