# 실제 공개자료 기반 시나리오·메모 구조 초안

2026-10-18 KST · v1 검토 초안

> 후속 설명에 따라 **[v2 미공개 개발 시점 업무 시뮬레이션·진행 리뷰](../internal_pipeline_v2/01_REVIEW_WALKTHROUGH.md)**를 추가했다. v1은 공개자료 정리/메모 기능 예이고, 결과를 모르는 상태에서 합성 내부 실험·응답으로 일하는 흐름은 v2를 먼저 읽는다.

사용자의 ‘실험자료·코멘트는 실제 데이터를 참고하여 작성’ 요청을 반영했다. **SB17/Pyzchiva의 실제 공개 실험 요약과 EMA/CHMP 평가를 내부 업무 양식으로 재구성**한다. 기존 v0의 임의 수치 97%·94%·96%, 내부 목표 90~110%, 무효 run·재시험 이야기는 채택하지 않는다.

## 먼저 볼 내용

질문과 정답을 먼저 비교하려면 [공개 개발용 정답셋 12개](06_GOLD_CASES.md)를 읽는다. 질문별로 입력 범위·정답 예시·필수 사실·허용 표현·오답 조건·근거 위치를 함께 둔다. [기계 판독용 정답 명세](05_GOLD_CASES.json)도 같은 케이스 ID를 사용한다.

1. [시나리오 초안](01_SCENARIO_DRAFT.md): 실제 사례의 쟁점과 재구성한 업무 흐름.
2. [내부 업무 문서 초안](02_SOURCE_DOCUMENTS.md): 공개 실험 요약을 바탕으로 작성한 검토 문서·코멘트·미팅 자료의 실제 본문.
3. [정보 단위와 세 업무의 출력 예시](03_STRUCTURED_MEMO_AND_TASKS.md): 같은 자료를 결과 검토·협력사 미팅·기관 질문/예상 질의 준비에 사용하는 모습.
4. [실제 자료 확인 원장](04_REAL_SOURCE_LEDGER.md): 수치·방법·의견의 근거 페이지, 원본 PDF, 미공개 정보와 재구성 범위.
5. [현재 메모 구조 점검·수정 제안](../../project/MEMO_STRUCTURING_REVIEW_2026-10-18.md): 실제 저장 메모 확인 결과와 코드·화면·저장 구조의 보완 순서.

## 핵심 사례

| 구분 | 확인한 내용 |
|---|---|
| 원사례 | SB17/Pyzchiva와 EU-Stelara 비교, IV vial 130 mg 맥락 |
| 실제 보고 관측범위 | FcRn 결합 활성 98~102% |
| 해당 사례 비교 범위 | similarity range 107~127% |
| 실제 검토 맥락 | C-terminal Lys variant, CPB 처리 보조 자료, PFS/IV 제형·대조약 범위 설정의 차이 |
| 실제 기관 판단 | 해당 근거와 맥락을 종합해 생물학적으로 의미 있는 영향이 예상되지 않는다고 판단 |
| 원출처 | EMA/106045/2024, PDF p.30~31·33~36; 세부 대조는 확인 원장 참조 |

98~102%는 개별 lot 원자료·평균이 아닌 공개 보고 범위다. 107~127%는 해당 사례의 similarity range이며 보편적인 규제 합격선이나 출하 규격으로 사용하지 않는다. 원문에서 공개하지 않은 lot별 값·실험 일자·SOP 버전·시험자·CPB 전후 수치는 만들어 채우지 않는다.

## 실제 사실과 재구성의 경계

- **실제 자료:** 공개 보고서의 수치·assay·제형·비교 범위·신청자 설명·CHMP 판단. 항목별 페이지를 붙인다.
- **재구성한 업무 문서:** 내부 검토 코멘트·확인 요청·가상 역할·미팅 일정·제안 행동. 실제 회사 발언·합의·기관 요구로 표시하지 않는다.
- **공개되지 않은 자료:** 미공개/확인 필요로 남긴다. 자료가 없었다는 결론으로 바꾸지 않는다.

실제 비공개 내부 문서를 입수한 것이 아니며, 실제 제품의 수치를 가상 자사 후보의 실측값으로 바꾸지 않는다. 단계별 자료 공개·읽기 순서는 데모 장치이며 실제 심사·실험 연대를 재현한 것이 아니다.

이 문서 묶음은 사람이 먼저 읽고 검토할 데이터·정보 구조 초안이다. **후속 작업으로 메모 항목화 기능과 6개 항목의 수동 재현 예를 앱·DB에 반영했다.** [직접 확인 방법·구현 범위·검증 기록](../../project/MEMO_ITEMS_IMPLEMENTATION_2026-10-18.md)을 참고한다. 9개 REPLAY 문서 전체의 검색 적재나 20개 예시 항목 전체의 구현은 아직 아니다. 시나리오 설명·확인 원장·업무별 기대 출력은 원문과 구분하여 관리한다.

## 정답셋의 쓰임

- 실제 공개 근거의 수치·방법·귀속, 미공개 정보와 잘못된 전제는 출처와 대조하는 정답으로 둔다.
- 합성 일정·공유 규칙은 합성 시나리오 안에서만 성립하는 정답으로 표시한다.
- 미팅 코멘트·결과 검토 브리프·기관 질문은 유일한 문구 정답 대신 필수 요소와 금지 결론으로 채점한다.
- 모든 정답은 사용자가 볼 수 있는 개발·데모용이다. 출처 대조 정답 초안이며 전문가 인증이나 미노출 평가셋으로 표현하지 않는다.
- 최초 실행 상태는 `not_run`이다. 실제 실행 결과·검색/답변 점수는 아직 없다.

평가 입력은 질문과 허용된 REPLAY 문서로 제한하고, 정답·예상 출력·사실 원장은 채점 측에만 둔다. T1의 부분 공급 조건에서는 전체 PDF의 다른 절을 입력하지 않는다. 원본 전체 PDF를 검색하는 평가는 별도 조건이다. 이 파일을 만든 것만으로 서비스에 입력 제한이나 채점기가 구현된 것은 아니다.
