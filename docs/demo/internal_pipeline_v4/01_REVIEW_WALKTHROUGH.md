# v4: 내부 자료로 업무 초안을 쓰는 기능 — 구현, 실행, 보완 결과

2026-10-18~19 KST. 설명용 한 장 요약은 [00 개요](00_OVERVIEW.md)에 있고, 이 문서는 구현·실행·보완 과정을 순서대로 기록한다. v2·v3는 격리된 실험 스크립트였고, v4는 같은 흐름을 **앱 기능**으로 옮긴 뒤 새 시나리오로 실행하고 보완한 결과다.

## 1. 한 줄 요약

파이프라인에 사내·협력사 문서를 등록하면 고른 **기준일**에 존재한 자료만으로 세 가지를 볼 수 있다. 원문 기록에서 계산한 **업무 상태판**, 버전·적용 여부가 표시된 **문서 목록**, 그리고 근거 칩과 자동 검사가 붙은 **업무 초안**(판단/근거/공백/다음 행동)이다. 시나리오 기준일 4개를 실제 모델로 실행했고, 최종 코드에서 5개 초안 중 4개는 리뷰 기준을 충족했다. 남은 1개(협력사 공유용)의 한계는 6절에 적었다.

자동 검사 경고는 1·2·6회차에 1건씩 나왔고 모두 오탐이었다. 고친 검사기로 모든 회차를 다시 검사하면 0건이다. 이것을 "오류가 없다"로 읽으면 안 된다. 검사가 잡는 범위가 좁다.

## 6. 남은 한계

1. **협력사 공유용은 사내 판단에서 나오는 안건을 만들지 못한다.** 공유용 입력에는 사내 계획서·분석자 가설이 없어서 IV 결과가 "문제"라는 맥락이 약하다. 사내 자료를 몰래 읽히면 누출 위험이 있다. 그래서 다음 단계로 **2단계 방식**을 권한다. 사내 초안을 먼저 만들고, 그 안건 중 공유할 항목을 사람이 고른 뒤 공유본을 만든다.
2. **같은 입력에도 응답이 달라진다.** 회차마다 표본은 1개다. T2 안건 개선은 2/2회로 확인했지만 표본이 작다.
3. **자동 검사는 좁은 한국어 정규식이다.** 실행 중에 오탐 두 종류를 고쳤고, 놓치는 오류가 있을 수 있다. 초안은 항상 "검토 전" 상태로 표시된다.
4. **검색 규모:** 31개 단위는 대부분 기준일에 전부 공급됐다(T4만 30/31). 수백 건 규모의 검색 성능은 검증하지 않았다.
5. **전문가 검토 없음, 합성 자료.** 실제 허가 결과를 예측하는 정확도와는 무관하다.
