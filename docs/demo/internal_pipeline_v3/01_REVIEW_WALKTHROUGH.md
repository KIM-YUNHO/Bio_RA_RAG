# 중단 지점부터 이어서 진행한 결과: 메모가 현재 업무에 맞게 적용되는가

**이 문서 하나를 순서대로 읽으면 된다.** 이전에는 시나리오를 한 번 실행해 문제를 찾았고, 이번에는 그 문제를 저장 구조와 답변 생성 흐름에 반영한 뒤 다시 실행했다.

**결과:** S2·S3의 업무 상태 혼동과 발언 주체 표시는 개선됐다. S1의 ‘합의문 자료 미제공 → 미합의 단정’은 본문에 남아, 자동 초안을 **검토 필요**로 표시했다. 상태 표의 정확성과 생성 문장의 정확도를 별도로 확인해야 한다는 결과다.

## 1. 이어서 해결한 문제

이전 모델은 IV 재분석·PFS 탐색 결과를 이미 받은 시점에도 초기 요청 문서를 인용하며 “현재 협력사 수락이나 납기 합의는 없다”고 넓게 썼다. 초기 문장의 출처는 맞지만 적용 시점·업무 범위가 틀렸다.

또 한 메모 안에 실험 수치와 “오류를 발견하지 못했다”는 분석자의 의견이 함께 있었고, 최종 답변에는 `승인·제출·수용 여부: .`라는 불완전한 문구도 남았다.

이번에는 다음을 구현했다.

| 보완 | 실제 변경 |
|---|---|
| 실험과 의견 분리 | 재분석 수치는 U06, 김분석의 기술 검토 의견은 U12에 저장. CMC 박개발과 RA 한규제의 의견도 U09/U16으로 분리 |
| 업무 범위 분리 | IV 재분석 / PFS CPB 탐색 / 추가 IV CPB / 모의 기관 답변에 각각 식별자 부여 |
| 현재 상태 갱신 | 해당 업무·해당 상태 축의 요청/회신 기록만 연결. 이전 상태와 출처도 보존 |
| 자료 부재 구분 | 합의문 자료 미제공, 명시적 미합의, 명시적 미실시를 다른 값으로 기록 |
| 승인 단계 분리 | 결과 회신·기술 의견·QA 승인·회사 답변 승인·제출·기관 판단을 별도 상태로 취급 |
| 답변 길이 제한 | 판단·근거·공백·다음 행동 네 칸, 각 최대 세 항목으로 생성 |

## 2. 사례와 실험 데이터는 그대로 이어간다

실제 SB17의 FcRn 공개 집계 범위와 과학적 쟁점에서 출발한 **P17 개발 시점 모사**다. 이번에도 최종 CHMP 판단을 모델에게 주지 않았다.

| 자료 | 합성 시나리오에서 사용하는 내용 |
|---|---|
| IV 초기 관측 | 세 가상 lot의 98.0 / 100.0 / 102.0% |
| 비교 범위 | 해당 비교 계획의 107–127%. 출하 규격이나 보편적 합격선이 아님 |
| IV 재분석 | 98.3 / 100.1 / 101.9% |
| PFS 지지 관측 | 가상 전하 변이·Lys 분석과 CPB 전후 표. IV 직접 측정과 구분 |
| 검토·응답 | 김분석의 의견, 가상 협력사 회신, 박개발·한규제의 의견, 모의 기관 질문·회사 초안 |

개별 lot/run·지지 실험 수치·담당자 발언·기관 질의응답은 모두 합성이다. 실제 기업 내부 원자료를 확보한 것은 아니다. **관측 수치를 새로 유리하게 바꾸지 않고, 같은 내용의 정보 단위와 상태 표현을 보완했다.** 입력을 재구성했으므로 한 가지 변수만 바꾼 독립 실험이나 미노출 정확도 평가로 표현하지 않는다.

## 3. 첫 결과를 받은 시점 — S1

담당자는 초기 시험값과 비교 계획, 분석자 코멘트, 협력사 문의만 갖고 있다. 추가 재분석·PFS 결과·기관 의견은 아직 모델에게 공급하지 않는다.

현재 판단은 “세 요약값이 이번 비교 범위보다 낮다”까지다. 데이터와 run 상태는 잠정·확인 대기이고, 원인이나 제품/허가 결론은 확정하지 않는다. 먼저 원자료·계산·대조약 범위·run 검토 자료를 확인하는 흐름이다.

이 단계의 상태 표시에서 중요한 차이는 다음과 같다.

> “협력사에 요청했고 합의문이 아직 제공되지 않았다”와 “시험 범위·납기가 실제로 미합의다”는 같은 말이 아니다.

이번 내부 점검에서 이 둘을 다시 확인했고, S1의 합의 상태는 **합의문 자료 미제공**으로 저장했다. 초기 기록만으로 실제 수락 여부를 단정하지 않는다.

하지만 최종 모델 본문에는 “독립 재분석의 수락·실행 일정·납기는 아직 합의되지 않았다”는 문장이 남았다. 원문 상태와 대조하는 검사에서 이를 발견해 **S1을 검토 필요로 표시**했다. 리뷰어 수정 문구는 “독립 재분석의 수락·일정·납기 합의문이 현재 자료에 없어, 실제 합의 여부는 확인이 필요하다”다. 자동 출력 원문을 이 문구로 몰래 교체하지 않았다.

## 4. 결과 회신 뒤 미팅 준비 — S2

이 시점에는 IV 재분석과 PFS 탐색 결과가 추가된다. 새 상태 표는 모델이 자유롭게 요약한 문장이 아니라 **저장한 원문 이벤트를 업무별로 계산한 결과**다.

| 업무 | S2의 현재 상태 | 승인·검토와의 구분 |
|---|---|---|
| IV FcRn 재분석 | 결과 회신 자료 있음 | 김분석의 기술 의견 회신. QA 승인 자료는 미제공 |
| PFS CPB 탐색 | 결과 회신 자료 있음 | 잠정·기술 검토 중. QA 승인 자료는 미제공 |
| 추가 IV CPB | 미실시·범위와 납기 미합의 | 새로 협의할 업무. 앞선 두 작업을 미실시로 되돌리지 않음 |

기존 IV/PFS 시험의 정식 합의문은 현재 묶음에 없다고 표시한다. 그렇다고 결과 회신 자체가 없었던 것으로 취급하지 않는다.

**미팅 준비의 초점**은 이제 “모든 시험을 새로 요청”하는 것이 아니라, 회신한 결과의 원자료·한계를 확인하고 추가 IV CPB의 범위·시료·책임자·일정을 협의하는 것이다. PFS 자료는 IV 직접 관측이 아니지만, 연결 근거와 한계를 정리해 간접 지지자료로 검토할 수 있다.

**김분석의 의견**도 이름을 붙여 기록한다. “김분석이 계산 오류를 찾지 못했다고 회신했다”는 사실과 “시험이 독립 검증·QA 승인됐다”는 판단을 구분한다.

## 5. 기관 질의응답 연습 — S3

연습용 Q-01~03은 IV 범위 하회, PFS 자료의 IV 연결 근거, 생물학적·PK 관련성 평가를 묻는다. 모델은 각 문항의 판단·근거·공백·다음 행동을 작성한다.

회사 초안의 공식 상태는 별도 원문 기록에서 표시한다.

| 구분 | 이번 시나리오의 상태 |
|---|---|
| 회사 답변 승인 | 미승인 초안 |
| 회사 답변 제출 | 미제출 |
| 기관 질의·판단 | 모의 질의이며 실제 기관 판단 대상이 아님 |

따라서 빈 상태 문구를 채우기 위해 모델이 승인·제출·수용을 추측할 필요가 없다. 실제 공개 SB17 결론과의 대조는 [사후 공개 자료](../internal_pipeline_v2/03_REVEAL_AND_REVIEW_CRITERIA.md)에서만 한다.

## 6. 실제 재실행 결과와 전후 비교

최종 답변 원문과 실행 숫자는 [04 자동 출력](04_GENERATED_DRAFTS.md), [05 실행·검토 기록](05_RUN_REVIEW.json)에 보존했다. 새 결과를 읽을 때는 아래 네 가지를 확인하면 된다.

| 질문 | 이전 항목 수 | 이번 항목 수 | 검토 결과 |
|---|---:|---:|---|
| S1 결과 검토 | 13 | 11 | 상태 표는 자료 미제공으로 구분. 본문의 미합의 단정은 검토 필요로 탐지 |
| S2 협력사 미팅 | 15 | 12 | 기존 두 작업의 결과 회신과 추가 IV CPB의 미실시·미합의를 분리. 김분석 의견 명시 |
| S3 기관 답변 | 16 | 12 | 위 업무 구분 유지. 미승인·미제출·모의 기관 상태를 원문 이벤트에서 표시 |

최종 재실행은 동일한 모델 `gpt-5.6-luna`로 세 질문·호출 3회다. 이번 이어하기 중 S1 상태 표현을 다시 점검하기 전 중간 실행도 3회 있었으므로 **이번 작업 전체 호출은 6회**다. 이전 v2의 입력·답변과 중간/최종 실행 원문을 각각 보존했다.

저장·상태 갱신·미래 자료 차단·원문 역할 보호·두 HTTP 서버·PostgreSQL·기존 UI 계약을 포함한 **전체 테스트 78개가 통과**했다. 앞서 실행한 76개 전체 검사와 19개 관련 검사를 합산한 숫자가 아니라, 마지막 전체 실행의 서로 다른 테스트 수다. 입력 원문과 코드 스냅샷은 로컬 실행 폴더에 보존했고, 중간/최종 입력은 각 실행 당시 SHA-256과 일치함을 확인했다.

1. S2·S3에서 **IV 재분석/PFS 결과 회신과 추가 IV CPB의 미실시·미합의가 구분되는가**.
2. 기술 의견을 쓸 때 **김분석 등 발언 주체가 표시되는가**.
3. 회사 초안의 **미승인·미제출·모의 기관 상태가 빠짐없이 표시되는가**.
4. 답변이 네 칸·최대 12항목으로 정리되는가.

자동 검사는 공급 시점·원문 식별자·형식·업무 이벤트 계산을 확인하며, 문장의 과학적 의미 전체를 인증하지 않는다. 모델 출력의 재사용 가능성과 남은 표현 문제는 실행 뒤 별도 검토 기록에 구분해 적었다.

본문 일관성 검사는 부재를 미합의로 단정하는 표현 일부를 찾는 **좁은 규칙 기반 검사**다. 모든 모순을 알아내는 검증기가 아니다. S2·S3도 ‘승인된 답변’이 아닌 검토 전 초안으로 표시했다. S1·S2에서 일반 확인 질문에 Q-01~03 번호를 붙인 표현은 S3의 모의 기관 문항과 혼동할 수 있어 ‘안건 1/2/3’으로 정리하는 편이 좋다.

## 7. 실제로 사용할 때 남아 있는 범위

현재 구현은 **격리한 시나리오와 저장 메모를 사용하는 실행**이다. 저장 기능·상태 계산 코드는 앱 모듈에 추가했지만 운영 앱의 전체 pgvector 검색·내부 문서 업로드 화면에 연결한 상태는 아니다. 기존 앱 DB와 v2 실행 원문은 보존했다.

실제 업무에 연결할 다음 단계는 결과·요청·회신 문서에서 이 필드를 추출하고 검토하는 흐름, 시험/업무 식별자 매칭, 상태 충돌 표시, 프로젝트·공유 범위 필터다. 임상적 의미·허가 가능성을 이 작은 합성 사례의 자동 검사 통과로 보증하지 않는다. 먼저 이 리뷰와 결과를 기준으로 실무적으로 필요한 항목의 구성부터 확인할 수 있다.
