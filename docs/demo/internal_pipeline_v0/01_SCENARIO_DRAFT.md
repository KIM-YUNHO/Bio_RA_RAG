# 내부 파이프라인 데모: DEMO-U01 시나리오 초안

> 대체된 초안. 아래 97%·94%·96%, 90~110% 및 무효화·재시험 이야기는 임의 합성 예시다. 현재 검토 대상은 [실제 공개자료 기반 v1](../internal_pipeline_v1/README.md)이다.

작성: 2026-10-18 KST · 버전: 0.1 · 상태: 검토용 합성자료

이 문서와 [합성 원문 10개](02_SOURCE_DOCUMENTS.md)의 회사·인물·제품·실험·계약·날짜·숫자는 모두 가상이다. `DEMO-U01`은 우스테키누맙 후보를 가정한 개발코드이며, CRO **가온분석**과 CDMO **누리바이오**도 이 데모에서 만든 가상 회사다. 같은 이름의 실제 회사와 무관하다. **90~110%는 이 이야기의 가상 사내 개발 목표다. 실제 규제기관 허용 기준, 품질 규격 또는 출하 기준이 아니다.**

현재 서비스에 적재하지 않은 사람이 읽는 초안이다. 독립 평가용 정답 세트가 아니며 아래 설명을 향후 검색 코퍼스에 넣지 않는다.

## 한 번 읽어볼 이야기

개발팀은 DEMO-U01 배치 `DU01-B01`의 상대활성을 가온분석에 맡겼다. 승인된 내부 검토계획은 시험 유효성이 확인된 상대활성 결과를 **90~110%의 내부 목표**와 비교하도록 정했다. 개발 담당자는 개발 가정을 바탕으로 97%를 예상했지만 이는 관측 결과가 아니다.

가온분석은 8월 14일 이메일에서 8월 21일 최종보고를 목표로 한다고 말했다. 체결된 SOW의 납기는 8월 28일이며, 이 이메일은 계약을 변경한 합의서가 아니다. 8월 18일 전달된 최초 결과는 94%였지만 시험 유효성 확인과 검토가 끝나지 않은 잠정값이었다.

8월 19일 내부 CMC 담당자는 “숫자 자체는 목표 안이므로 일정 유지를 검토할 수 있다”고 의견을 남겼다. 같은 메모에는 “시험 유효성 확인이 우선이며, 추가 실험 생략이나 허가 가능성을 결론 내릴 수 없다”는 조건도 있다. 이 의견은 실험 관측값이나 승인된 의사결정으로 바뀌지 않는다.

8월 24일, 최초 시험의 대조시료 준비기록에 문제가 확인되어 해당 run이 무효화됐다. 94%는 과거 기록으로 남지만 유효한 제품 결과로 사용할 수 없다. 8월 25일 양측은 재시험과 최종보고 일정을 다시 합의했다. 누리바이오가 제출할 별도 순도 자료도 아직 없으므로 상대활성 한 항목만으로 전체 패키지를 평가할 수 없다.

9월 4일 재시험 보고에는 96%가 관측됐고 해당 run의 유효성이 확인됐다. CRO 최종보고 승인은 끝났으나 사내 통합 검토는 9월 9일까지 진행한다. 9월 8일 미팅을 준비하면서 CRO에 받을 자료와 규제기관에 확인할 평가 접근 질문을 분리해야 한다.

## 실제로 던져볼 세 요청

### 1. 내부 결과와 기준 비교

> 2026년 8월 19일 기준으로 DEMO-U01의 예상값 97%와 잠정 결과 94%를 보면, 내부 목표에 들어오는 수준인가? 확정해서 말할 수 없는 부분과 참고할 문서를 함께 정리해줘.

이 요청은 수치의 범위 비교와 데이터 상태를 함께 보여줘야 한다. 예상값·잠정값을 두 개의 확정 실험결과처럼 합치지 않는다. 8월 25일 기준으로 다시 물으면 무효화 기록을 반영해야 하고, 9월 7일 기준으로 물으면 유효한 재시험 결과를 제시해야 한다.

### 2. 협력사 미팅 코멘트

> 9월 8일 가온분석 미팅용으로, 약속한 일정과 실제 진행이 달라진 부분에 코멘트를 달아줘. 받을 자료·담당자·다음 날짜도 정리하고, 외부 전달본에는 가온분석에 공유 가능한 내용만 넣어줘.

일정의 이메일 목표, 기존 체결 SOW, 8월 25일 변경합의를 순서대로 연결한다. 최초 94%를 유효한 결과로 인용하지 않으며, 내부 의견 메모의 “대체 CRO 검토”는 외부 전달본에 넣지 않는다. 누리바이오 문서 원문도 가온분석에 자동 전달하지 않는다.

### 3. 규제기관 사전 질문

> 이 쟁점을 다음 FDA 미팅에서 확인하려고 해. 우리 데이터와 회사의 제안을 구분해서 질문 초안을 준비하고, 아직 없는 자료를 적어줘.

FDA는 이 초안의 가상 준비 대상일 뿐이다. 실제 FDA 회신·사전 동의·규제상 합격 기준은 데이터에 없다. 질문의 배경, 최초 run 제외와 재시험 결과의 제시 방법, 누락 자료, 회사 제안을 정리한다. 관련 공개 지침은 별도로 현행성을 확인하고 원문을 연결해야 한다.

## 문서와 메모를 묶을 때의 읽는 단위

문서 하나를 통째로 “실험” 또는 “의견”으로만 분류하기보다 **실험을 공통 연결축으로 두고 문장별 역할을 보존**한다. DEMO-D06은 문서 종류가 내부 의견 메모지만, 그 안에서 인용한 94%의 원출처는 DEMO-D05다. 그 수치와 “일정 유지를 검토하자”는 의견이 같은 승인 상태를 갖지 않는다.

- **실험 묶음:** `EXP-U01-ACT-001` 아래 배치·시험법·RUN-A01/RUN-A02와 관련 원문을 연결한다.
- **결과 항목:** 97%는 예상, 94%는 잠정 후 무효, 96%는 CRO 확정·유효라는 상태 이력을 별도로 둔다.
- **기준 항목:** `CRIT-U01-ACT@1.0`을 결과와 연결하되 기준 충족과 전체 제품 판단을 구분한다.
- **의견·제안:** 작성자·날짜·조건을 남기고, 합의·승인 기록이 없으면 결정으로 바꾸지 않는다.
- **업무·일정:** SOW·이메일·변경합의를 각각 연결해 약속의 강도와 변경 근거를 보존한다.

저장된 자유서술 RAG 메모도 같은 방식으로 연결할 수 있다. 원문을 유지하고, 사람이 확인할 추출 후보로 실험 ID·문장 역할·근거 위치를 제시하는 방식부터 검토한다. 실제 저장 스키마 변경이나 자동 분류는 이번 초안에 포함하지 않았다.
